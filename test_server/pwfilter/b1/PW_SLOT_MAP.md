# ★★★ PW 槽位真值表（2026-10-04 13:58 特征色实机定案）

> 起因经过：木一先指出"UI 只有 3 个自定义槽"，我扫出 enum 表后误判"slot 11 是无效空洞"，
> 木一用特征色实测推翻 → **slot 11 完全有效，就是自定义3。**

## 一、★ 核心结论：两个编号空间不能混淆

| 编号空间 | 编号 | 含义 |
|---|---|---|
| **prefman slot**（存参数） | 0–13 | 14 槽：`0-8`=厂商9个，`9/10/11`=自定义1/2/3，`12`=?，`13`=? |
| **setusr enum**（切风格） | 0–12 | `0-8`=厂商9个，`9`=自定义1，`10`=自定义2，**`11`=空洞被拒**，`12`=自定义3 |

### 映射关系（实机验证）

| UI 显示 | setusr enum | DATA ID | **prefman slot** |
|---|---|---|---|
| STANDARD ~ CALM | 0–7 | 0x140000–0x140007 | 0–7 |
| **CLASSIC** | **8** | 0x140008 | **8** |
| 自定义1 | 9 | 0x140009 | **9** |
| 自定义2 | 10 | 0x14000a | **10** |
| 自定义3 | **12** | 0x14000c | **11** ← 错位 1！ |

**★ 关键：enum 12（自定义3）实际指向 prefman slot 11，两者错位 1 位。**
**★ 我上一轮把"enum 11 被拒"误读成"slot 11 无效"，这是错的——被拒的只是那个 enum 值。**

## 二、验证方法（可复现）

在slot 9/10/11 写入特征色（**不save**），UI 上逐个选自定义 1/2/3：

| slot | 写入值 | UI 显示 | 结果 |
|---|---|---|---|
| 9 | 200/60/60 | 自定义1 | **强红** ✅ |
| 10 | 60/200/60 | 自定义2 | **强绿** ✅ |
| 11 | 60/60/200 | 自定义3 | **强蓝** ✅ |
| 12 | 240/240/40 | （UI 无此项） | 不可见 |
| 13 | 200/60/200 | （UI 无此项） | 不可见 |

## 三、★★★ 顺带定案：prefman set 不 save 也实时生效

**木一在未 `prefman save` 的情况下就看到了强红/强绿/强蓝。**

**→ 修正上一轮的结论。** 之前我写"必须 save 才能生效"是错的——
真正导致回退的是我多加了 `prefman load -a 0`（那一步会从 eMMC 重载、覆盖刚写的值）。

**正确结论：**
```
prefman set 7维→ ISP 立即采用（不需 save，不需 load）→ ★ 实时生效
prefman load -a 0  → 从 eMMC 重新加载，会【覆盖】刚 set 的值（方向相反）
prefman save       → 只写 eMMC 持久化，对实时生效无必要
```

**★ 这意味着配方切换可以做到：写 1 个 slot + 切 1 个 enum = 零 eMMC 写入、零磨损、毫秒级。**

## 四、修正后的 8 配方槽位分配

| slot | enum | 配方 |
|---|---|---|
| 9 | 0x140009（自定义1） | portra400 / monowarm / vignette |
| 10 | 0x14000a（自定义2） | velvia50 / hp5 / superia400 |
| 11 | 0x14000c（自定义3） | trix400 / ektachrome |

**每次切换 = 写 1 槽（7 维，不 save）+ 切 1 enum。**
槽位 12/13 在 UI 上不可见，不使用。

## 五、设计方案（现在可以定了）

既然实时生效已被验证，**方案 B（预写 + 只切枚举）成为最优**：

| 方案 | 做法 | 特性 |
|---|---|---|
| **A 每次写槽** | 写 1 槽 + 切 1 enum | 配方无限，但每次都写内存（其实也很快） |
| **B 预写 3 个** | 装机时写满 3 槽，之后只 `setusr` 切 enum | **零写入、毫秒级、UI 上直接可选** |
| **C 混合** | 3 槽预写常用 + 其余走 Web 台 | 配方无限，UI 零延迟 |

**推荐 B 或 C。** 关键结论：**3 个可见槽不是限制，因为切换一个配方只要写 7 个整数 + 1 条 setusr。**

## 六、UI 顺序 ≠ enum 顺序（做前端要记住）

```
UI:  OFF / STANDARD / Classic / VIVID / PORTRAIT / LANDSCAPE / FOREST / RETRO / COOL / CALM / 自定义1 / 自定义2 / 自定义3
enum:0/    0     /    8    /   1    /    2     /     3     /    4    /   5    /  6   /  7   /   9     /   10    /   12
```
**CLASSIC 在 UI 排第 2 但 enum=8，顺序完全不同。做 Web 配方台必须按 UI 顺序排。**
