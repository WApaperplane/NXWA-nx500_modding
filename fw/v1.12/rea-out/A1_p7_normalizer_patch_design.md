## 0. TL;DR

**只需 2 处修改**即可打通外部 setvar 直写 R/G/B/HUE：

| # | 位置 | 原内容 | 新内容 | 大小 |
|---|---|---|---|---|
| 1 | file `0x510b0`（VA `0x800510b0`） | `ea 0000b7`（b 0x80051394 拒收） | `b <特判块>` | 4B |
| 2 | 空闲区（候选见 §4） | 全零 | **特判块 24B**（见 §3） | 24B |

**原理**：外部 id `0x130–0x133`（ext_id）经 `FUN_00051090` 归一化时，原逻辑落在"越界拒收"分支；把该分支重定向到"特判块"，由特判块对 `0x130–0x133` 做**恒等映射**（内部 id = 外部 id），其余越界值仍走原拒收。**所有现有 handler、跳转表、收尾代码零改动。**

## 1. 对象结构（全部逐字节核实）

### 1.1 FUN_00051090 完整布局（file off = VA - 0x80000000）

```
0x51090  序言 + 域检查 + 跳转（9 指令，36B）
  push {lr}; cmp r1,#0; sub sp,#20; mov r2,r0; beq 0x513cc
  sub r3, r0, #0x100        ; r3 = ext_id - 0x100
  cmp r3, #0x2e             ; 合法域 = 0x100..0x12e
  ldrls pc, [pc, r3, lsl #2]  ; 跳转表（表固定在 0x510b4，pc 相对不可搬迁）
  b 0x51394                 ; ★ 越界 → 拒收（本方案修改点 #1）
0x510b4  跳转表 47 项 ×4B（id 0x100..0x12e → handler 指针）
0x51170  item[46] handler（id 0x12e → 内部 0x13f）：movw+str+内联收尾（20B）
0x51178  共享收尾：mov r0,#0; add sp,#20; ldmfd sp!,{pc}
0x51184  handler 群 44 个（12B/个：movw/mov r3,#<内部id>; str r3,[r1]; b 0x51178）
0x51394  拒收 handler：mov r3,#0xff; str r3,[r1]; ...日志...; mvn r0,#0; b 0x5117c（返回 -1）
0x513cc  r1==0 分支：mvn r0,#0; b 0x5117c
0x513d4  3 个字面量（日志用）
0x513e0  下一函数（编码 LUT getters）
```

### 1.2 调用者契约（PW_ID_MAP §6，已交叉核对）

```c
FUN_0004ccf4(ext_id, val, sz):
    iVar1 = FUN_00051090(ext_id, &conv);   // conv 输出内部 id
    if (iVar1 == 0) FUN_000d6b20(conv, val, sz);  // 成功：发送
    else { 记日志; return -1; }                    // 失败：拒收
```

- 返回值 = 0 → 成功；-1 → 拒收。
- **特判块只需保证**：目标 id 返回 0 + conv=ext_id；其余越界值返回 -1。**完全兼容原契约。**

## 3. 特判块（24B，终稿）

```
特判块（入口：r0 = ext_id（>0x2e 的越界值）, r1 = &conv, sp 已 -20）：
  sub   r3, r0, #0x130      ; r3 = ext_id - 0x130
  cmp   r3, #3
  bhi   0x80051394          ; 非 0x130-0x133 → 原拒收（r0/r1/sp 状态未污染，兼容原拒收路径）
  str   r0, [r1]            ; conv = ext_id（恒等映射：外部 id 0x130..0x133 即内部 id）
  mov   r0, #0              ; 返回 0（成功）
  b     0x8005117c          ; 原共享收尾（add sp,#20; ldmfd sp!,{pc}）
```

**字节序（小端）与编码 —— ★ 已用 arm-linux-gnueabihf 汇编器实测验证（假设放置于 0x11504）**：
```
0x11504: e2403e13  sub  r3, r0, #0x130     ; 0x130 合法立即数（0x13<<4，8bit 旋转编码）✓
0x11508: e3530003  cmp  r3, #3
0x1150c: 8a00ffa0  bhi  0x80051394         ; 验证：0x80011514 + 0xFFA0*4 = 0x80051394 ✓
0x11510: e5810000  str  r0, [r1]
0x11514: e3a00000  mov  r0, #0
0x11518: ea00ff17  b    0x8005117c         ; 验证：0x80011520 + 0xFF17*4 = 0x8005117C ✓
```
**完整字节流（24B）**：
```
13 3e 40 e2 | 03 00 53 e3 | a0 ff 00 8a | 00 00 81 e5 | 00 00 a0 e3 | 17 ff 00 ea
```
> ★ **位置敏感**：`bhi` / `b` 的偏移随特判块最终放置地址重新计算。
> 生成命令：`arm-linux-gnueabihf-as` + `ld -Ttext=0x80011504`（见 `tools/wsl-sh/asm_verify.sh`，已复现上述编码）。
> 若最终选在别的位置（如 0x11010 / 0x57c11c），用同一脚本改 `-Ttext` 重生成即可。

**bhi 的判定边界**：bhi = C=1 且 Z=0（无符号大于）。r3 ∈ {0,1,2,3} → 不跳（继续）；r3 = -1（0xFFFFFFFF，对应 ext_id 0x12f）或 ≥4 → 跳拒收 ✓。
**ext_id < 0x130 的值**（如 0x100-0x12e）**不会到达特判块**（它们在跳转表内被处理）✓。

## 4. 特判块选址（3 个候选，按安全性排序）

> 判据：① 无代码引用（字面量搜索 0 命中）② 非运行时数据区 ③ 4B 对齐

### 候选 A：`0x11502`（254B 零区）★ 主候选
- **上下文**：T-Kernel 引导参数块尾部 —— `0x11000`(指针表头) + `0x11080`(默认配置文本 "TSysName…PmMaxProg") + `0x114c4`(可覆盖配置文本 "DEBUGMODE/NETDEV0/RAMDISK") + **`0x11502–0x115ff`(254B 零)** + `0x11600`(启动代码/内存初始化)。
- **引用检查**：`0x80011502` / `0x80011540` 字面量 **0 命中** ✓
- **风险**：该区可能属"配置覆盖预留"——若启动/工厂流程按固定大小写该块，会覆盖补丁。**待 REA/Ghidra xrefs 终极确认 + 灰度测试（§6）实测确认**。
- 建议放置点：`0x11504`（4B 对齐）或 `0x11540`（区中部）。

### 候选 B：`0x11010`（112B 零区）
- **上下文**：引导参数块指针表（0x11000-0x1100f）之后、配置文本（0x11080）之前。
- **引用检查**：`0x80011010` 字面量 **0 命中** ✓
- **风险**：同 A（结构保留字段）；且更靠近"结构头"——被"整块复制"的概率略大。

### 候选 C：`0x57c11c`（280B）/ `0x57bdbc`（760B）等 0x57xxxx 数据区零洞
- **上下文**：数据/名字残骸区（0x584990+ 已判为 Itanium 名字残骸）——数据性的零洞。
- **风险**：若属"运行时写入的数据结构"，会被覆盖。**优先级低于 A/B。**

### 排除项
- 0x11010-0x114c3 文本区中不可插（文本被解析）。
- 0xa3dc 27KB 零区（早期数据段，疑似运行时 .data/.bss）——排除。
- 固件尾部（数据/指针数组）——排除。

## 5. 改动后行为变化评估

**为什么"改归一化器"是当前唯一可行路（论证链）**：

1. 外部（Linux 侧）一切参数推送都经 MCB 两扇门：`SetUserDataMCB(|0x1100)` / `SetVariableDataMCB(|0x1300)`（`ATTR_BUS_MCB`+`PW_APPLY_TRIGGER_CHAIN §7.1` 字节级穷举，capfw 全库各 1 处构造点）
2. 变量门（0x1300）→ p7 侧唯一处理器 = `FUN_00051090` 归一化器（本方案目标）；
3. R/G/B/HUE 需要"内部 id 0x130–0x133"，而归一化器表输出集合不含它们 ⇒ 现状拒收；
4. "复刻 app 类别消息"路已 5 路取证证伪（无字节级实体）；"键注入"已实测不生效；
5. ⇒ **打开变量门对 0x130–0x133 的放行 = 成本最低、爆炸半径最小、与现有工具链（pwsend/pwcalib/值编码）完全兼容的路**

| 对象 | 变化 |
|---|---|
| `st cap capdtm setvar 0x130 <v> 4`（外部） | **新增可用**：归一化输出内部 0x130 → 经 FUN_000d6b20 发送 → R 通道生效（预期） |
| 同上 0x131 / 0x132 / 0x133 | **新增可用**：G / B / HUE |
| ext id 0x12f / 0x134+（越界） | **行为不变**（仍拒收，返回值 -1 与原一致） |
| ext id 0x100–0x12e（表内） | **行为不变**（不经过特判块） |
| 拒收 handler 共享路径（0x119/0x11a） | **行为不变**（不经过特判块） |
| p7 其他一切 | **零影响**（仅 1 条 b 指令 + 1 块死区数据变更） |

**收益**：外部全 7 维直推达成（SAT/SHARP/CON 已通 + R/G/B/HUE 打通）：
- FILMLAB_PW 直推全 7 维，`filmlab.sh apply` 一步到位；
- 值编码沿用既有：R/G/B = `(gain<<16)|0x00FF`（COLOR），HUE = SCALAR `(raw16<<16)|0xD80A`。

## 6. 上机验证设计（G4 后）

### 6.1 灰度两步法（零风险递进）

**Step 1 — 路径绕行自检（行为不变）**：
- 特判块先写为单指令 `b 0x80051394`（8B）；`0x510b0` 重定向到它。
- 行为与改前**逐位等价**（多绕一跳）。
- 触发越界调用（`setvar 0x12f` 或无效 id）→ 观察：p7 正常拒收 + 相机稳定。
- **若特判块区域被运行时覆盖**（内容被改成垃圾）→ p7 崩 / 拒收异常 → **立刻发现，损失最小**。
- 稳定运行（建议覆盖多种工况：拍照 / 录像 / 待机唤醒）≥ 数小时后进 Step 2。

**Step 2 — 完整特判块**：
- 写入 24B 完整逻辑。
- 判据：`pwcalib.sh probe3` → `0x130←12 / 0x131←13 / 0x132←14 / 0x133←15` → `readback` 命中 == 目标（PWCOLOR_R/G/B/PWHUE 跟随）。
- 对照：`0x110` SAT 写入仍正常（回归不变）。

### 6.2 回滚
- 本 patch 仅动 2 处字节，**保留原字节**（`ea 0000b7` + 24B 零）即可原地回滚。
- 若 U5 回滚演练已建立单分区恢复流程（G4-2），本 patch 随 p7 分区一起回滚。

### 6.3 判定边界（知情风险）
- 若 R/G/B/HUE 写后 `varlist` 有变化但**画面无感**：说明还有"渲染消费侧"条件（如 PWCOLOR 聚合项联动）——**另一层任务，不在本 patch 范围**。
- 失败不影响任何现有功能（Step 1 已证明路径中性与区域安全）。

## 8. 与上游设想的对照（为什么本方案更优）

上游 `PW_APPLY_TRIGGER_CHAIN §3 / TASKFLOW A1` 设想"**扩跳转表边界 + 补 0x130-0x133 handler**"。本方案实现同一目标但**显著更省**：

| 维度 | 上游设想（补 4 个 handler） | 本方案（恒等特判块） |
|---|---|---|
| 跳转表 | 47→52 项（+20B，需重排覆盖 handler 区）| **不动**（表尾 0x51170 区保持原样）|
| handler | 新写 4×12B + 处理"表扩容挤掉原 item[46] handler 与共享收尾"的搬迁问题（牵连 46 个 `b` 指令引用）| **0 个新 handler**（`str r0,[r1]` 通用恒等，4 个 id 复用同一段逻辑）|
| 收尾代码 | 需迁移（被表扩容覆盖）| **不动**（特判块直接 `b` 回原收尾 0x5117c）|
| 修改点 | 表×5 + handler×4 + 收尾搬迁 + 46 处 b 修正 | **2 处**（1 条 b 指令 + 24B 死区数据）|
| 回归风险 | 高（触及所有 handler 的跳转目标）| **极低**（现有路径零改动，只新增越界分支的重定向）|

**特判块还可进一步压缩**（如需）：r3 判断可改为"`sub r3,r0,#0x130; cmp r3,#3; bhi R`"之外的形式；但 24B 已满足所有候选区。
