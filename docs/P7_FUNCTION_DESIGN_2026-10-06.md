## 0. 结论前置

**P7 功能以第5 个主菜单项挂载，与现有 6 项平行，物理隔离。**
**唯一跨界操作（写 p7 分区）被单独隔离 + 四道门控 + 默认隐藏。**
⇒ 现有功能零破坏，p7 功能不装也能正常用。

---

## 1. 设计三原则（贯穿全部）

| 原则 | 具体做法 |
|---|---|
| ★★ **零破坏** | 只**新增**独立页面；现有 6 个 `gui_*` 页面一行不改语义；`FilmLab mkgui` 动态生成机制不受干扰 |
| ★ **危险隔离** | 所有 destructive 操作集中在 `gui_p7flash.NX500` 一页；**其余三页全是只读或只写寄存器**（不碰分区）|
| ★ **状态可见** | 每个写操作都配一个回读/验证项；不做"写了不知道成没成" |
| ★ **安全默认** | 刷写能力由 `p7flash.ok` 标记文件门控，**默认不开放** |

## 3. ★ 色彩方案页 = A 线主交付

### 3.1 4 档映射（p7 静态解出）
| 菜单 | 档 | 物理地址 | 内容特征 | 推测用途 |
|---|---|---|---|---|
| 标准 | 0 | `0x810fd100` | 非单调 | 风格化曲线 |
| **黑白** | 1 | `0x81101e00` | 完美线性 | ★纯 identity/灰阶 |
| 电影 | 2 | `0x81106b00` | = 档0 | 同标准 |
| **肤色** | 3 | `0x81115200` | R↑G↓ | ★ **暖调/肤色优化（出厂值）** |

### 3.2 为什么这是"零风险可交付"
1. **只写寄存器**，不写任何分区 ⇒ 结构上不可能变砖
2. 地址是**固件自己的常量**，不是我凭空造的
3. 出厂值已知（档 3 = 0x81115200 = 实测 `+0x00c` 原值）⇒ **随时可退回**
4. ★ **3D LUT 是软状态**：11 次实验全程无死机无变砖，触屏对焦即恢复

### 3.3 ★ 未验证项（必须在实机跑）
| 项 | 状态 |
|---|---|
| `SelCbCr_ch`（`+0x004` bits[1:0]）取值 | ★ **未解**。11 次实验一律写 0。设 `gui_p7ch.NX500` 就是为了逐值试探 |
| 换档后画面是否可辨| ★ **未验**。这正是 A1 的目标 |
| 各档是否需要不同 `SelCbCr_ch` | 未知 |

⇒ ★ **诚实的边界**：这一页现在能"写入成功"，但**不能保证"4 档视觉可辨"**。
　 若 4 档看起来一样 ⇒ 说明档位差异不由 `+0x0c` 单独决定，要回去查 p7 的 `FUN_0009a3e8` 选择逻辑。

## 4. ★ 刷写页 = 安全设计的核心

### 4.1 四道门控（`p7_flash_slp.sh`）
```
门① p7flash.ok 标记文件存在        ← 手动创建，默认不开放
门② p7_backup.bin 已存在           ← 强制先备份
门③ popup_ok 二次人工确认          ← "FLASH P7? RISK BRICK"
门④ 刷写前二次备份（防用户上次备份后又变了）
+  刷完立即 p7_verify.sh 回读校验
```

### 4.2 ★ 风险重新定性（重要修正）
| 常见认知 | 实际 |
|---|---|
| "刷 p7 会整机变砖" | ★ **不会**。p7 = ISP 固件，坏了表现为**画面异常**；Linux（p6/p13）仍活着 ⇒ **telnet 仍可用** ⇒ 还能救 |
| "变砖了只能返厂" | ★ **不会**。官方退路已验证：同版本 1.12 官方 `.bin` 改名 `nx500.bin` 走机身菜单 Firmware Update，同版本刷成功 |
| 真正会变砖的是什么 | ★ **boot0 / boot1**。我们不碰。`boot1` 已备份，**`boot0` 仍缺** |

⇒ ★★★ **所以动p7 的实际风险等级 = "中"，不是"高"。** 这是本设计敢于把它做进 UI 的前提。
⇒ ⚠️ **但 `boot0` 备份是硬前置**，未补齐之前不开放门①。

### 4.3 三层退路
```
第 0 层  10 分区备份（+ 待补 boot0）        ← 最后防线
第 1 层  3D LUT 基线恢复（软状态，零风险）    ← 最常用
第 2 层  官方 .bin 走机身菜单（已验证）      ← 主力退路
第 3 层  UART0 飞线（现状不可用，备用）      ← 终极
```

## 5. ★ 与 USB 安全通道的关系

见 `USB_SAFE_CHANNEL_2026-10-06.md`。要点：

| 通道 | 对刷固件的价值 |
|---|---|
| ★ **SSH/SFTP**（社区 Dropbear，v2.88 集成）| ★★★ **主通道**：加密 + 密钥认证 + SFTP 安全搬运 11.5MB 镜像 |
| telnet | ★ 兜底，**永不删**（唯一不能被自己锁死的）|
| `info.tgw` USB PTP | ★★ 免 WiFi 的第二触发链 + 高速导图 |
| USB 网卡 | ❌ **判定不可行**（内核无 gadget 模块，10 年前社区已判死）|

⇒ ★ **建议**：刷 p7 期间只开 SSH、关 telnet/ftp ⇒ 攻击面从"整个局域网空密码"缩到"单个密钥端口"。
