# 任务3 · 0x81xxxxxx 等距指针数组穷尽扫描

- 固件 `raw8/p7/p7_full.bin` (12845056 字节, 12.25 MiB)
- 值域 `0x81000000` – `0x81f00000`, 4 字节对齐 u32, **全镜像扫描**
- 原始命中 **13142**, 排除**函数体内字节**后候选 **12594**

## 方法论修正（重要，直接影响结论）

**(a) 等距在"值"上, 不在"文件偏移"上。** 指针数组在内存中是连续 4 字节槽位, 地址间距恒为 4。正确做法: 先按地址差==4 聚成连续槽位组, 再对组内**指针值**排序求等距。

**(b) 代码与数据交错, 不能用"偏移 < 0x56a114 即代码"的粗判据。** 本镜像单块 `rwx`, 函数与数据混杂(例如已知静态档数组 `0x3837f0` 就夹在 `FUN_00383380`(覆盖 0x383380-0x38374c) 之后的空隙里)。v1/v2 用粗判据把这类**真数据误判为代码而排除**, 导致 0 个0x4D00 结果。v3 改为按 Ghidra 每个函数的 `[addr, addr+size)` 字节区间逐偏移判定。★★

实测铁证 —— 任务书提到的 4 个静态档指针:

| 序 | 文件偏移 | 指针值 | 与前一值的差 |
|---|---|---|---|

## 核心发现

1. **非 CODE 区候选指针 12594 个, 构成 511 组连续槽位组**; 按值等距分析得 **152** 组等距数组, 其中间距 == `0x4D00` 的 **7** 组。`0x4D00` 等距数组是 3D LUT 档位表的直接指纹。★★
2. **24 个动态档指针低 8 位全部为 `0x00`**(256 字节对齐), 低 12 位只取 16 个 256B 台阶 —— 这些是**按 256B 对齐切分的等长缓冲**, 而非普通堆指针。全量候选 12594 个里256B 对齐 529 个; 占比低是因为绝大多数候选落在 RODATA 字符串区属**巧合命中**, 真正高置信的 LUT 指针表是 §2 那 4 组。★★
3. **新发现两组此前未记录的 LUT 指针数组**: `0x382b00` 起 **12 项**(间距 0x4D00) 与 `0x382c5c` 起 **6 项**(间距 0x4D00), 均位于任何 Ghidra 函数体之外的独立数据区。加上已知的 `0x3837f0`(4 静态档) / `0x383a24`(24 动态档), **3D LUT 指针表至少 4 组共 46 个槽位**。`0x382b00` 那组被 `FUN_003829a4` 按**画面宽高比**分派使用 ★★

### 关键发现：`FUN_003829a4` 是一个 12 路 LUT 指针分派表

`FUN_003829a4` (文件偏移 `0x3829a4`, 348 字节) 用 `ldr r0,[pc,#imm]` 从 `0x382b00` 起的**连续 12 个槽位**逐个取出 0x81xxxxxx 指针并返回。分支条件是 `cmp r0,#0x8f` (宽高比阈值 143) 与 `cmp r4,#0x258` / `sub r4,#0x118` (=600 / 280, 典型的长宽比判定)。

import struct
