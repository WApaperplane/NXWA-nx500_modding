# 三星NX500/NX1 魔灯研究进展：3D LUT 写入通路已实机打通
---
> ## ⚠️⚠️⚠️ 2026-06 晚·结论纠正声明（必读）
>
> **本文档中「导入 LUT 内容必须改 P7」这一结论已被推翻。**
>
> 当时把 `d5_ep_3dl_load_lut` 误当成"挂地址"（往 `+0x0c` 写一个地址让硬件自己去读）。
> 复核后确认它走的是 **WDMA 硬件 DMA**：数据放在**调用者自己的 CMA 缓冲**（`/dev/d5_sma`），
> 由硬件 DMA 搬进 3D LUT 内部 RAM ⇒ **完全不涉及 `0x81xxxxxx`** ⇒ **Linux 用户态可以导入任意 LUT**。
>
> | 项 | 定论 |
> |---|---|
> | 被推翻 | "LUT 数据缓冲在 p7 地址空间 ⇒ 必须改 P7" |
> | 成立 | **导入 .cube LUT：用户态可做，不需要改固件** |
> | 仍需改 P7 的唯一理由 | 要改**ISP 生成 LUT 的算法**（tone curve 能力），不是"搬数据" |
>
> 关键证据：`ConfigAccessMode → sub_3a888 @0x3a888`（静态函数，本次解开）
> → `OnOff(1)→Acc(0)→Acc(1)→SetAddress(自己的 CMA 地址)→SelLUT→rw_Start(1)`，
> 其中 `rw_Start(1)` = `+0x008 |=0x100 → &=~0x100`（write-1-clear 触发 DMA）。
> ★ 另：`+0x0c` 写固件常量地址（4 档切换）是一条**独立通路**，与导入无关。
>
> 详见 `docs/LUT_IMPORT_2026-10-06.md` 与 `.workbuddy/memory/topics/ep-3dlut.md`。

## 做了什么

### ✅ 已验证打通（4 项）

| 能力 | 状态 |
|---|---|
| 拿到 EP 图像引擎 10 个子块的**权威物理地址** | ★ 内核 ioctl 直接给，10/10 交叉验证 |
| mmap 读写 EP 寄存器 | ★ 实机验证 |
| mmap 读写 CMA 共享内存 | ★ 实机验证 |
| **按 P7 固件的 6 步序列写入 3D LUT** | ★★ **画面确实变了**（本人目视确认）|

关键突破点：写入必须严格按 P7 固件的 6 步握手序列，
其中**第 2、6 步（清脉冲位、清读侧标志）漏掉就完全无效** —— 我前 5 次实验全栽在这里。

```c
b[0x000] |= 1;              // OnOff
b[0x008] &= ~1UL;           // ★ 脉冲位先清零
b[0x008] |= 1UL;            // ★ 置位启动
b[0x00c] = lut_phys;        // 数据地址
b[0x004] &= 0xffffffcfUL;   // 通道选择
b[0x008] &= ~0x100UL;       // ★★ 读侧清理
```

### ★★ 决定性发现：三星内置了 4 套 LUT 方案

从 P7 固件里挖出 4 个预置 LUT 缓冲地址，读出内容后确认：

| 地址 | 内容特征 | 是什麼 |
|---|---|---|
| `0x81101e00` | 完美线性 | 纯 identity（不改色）|
| `0x81115200` | R↑ G↓ 递变 | ★ 暖色调 / 肤色优化 |
| `0x810fd100` | 非单调曲线 | 风格化调性 |
| `0x81106b00` | 同第 1 个 | 同上 |

格式：**17³ 三维LUT，16-bit 三通道交织**。

### ⇒ 为什么最终要改固件

这 4 个缓冲在 `0x81xxxxxx`，而：
- Linux 只有 `mem=512M`（上限 `0x20000000`）
- P7 的页表只覆盖 `0x80000000..0x80ffffff`

⇒ **Linux 用户态永远碰不到这些地址。**

★ 注意这个理由很重要：不是"写入者在固件里"，
而是"**LUT 数据缓冲本身就住在 P7 的地址空间**"。
区别在于 —— 前者是猜测，后者是实测 + 源码 + 页表三重证据。

## 🎁 零风险可立即使用

**4 档内置色彩切换** —— 把 3DLUT 的 `+0x0c` 写入上述四个地址之一即可：

```c
b[0x00c] = 0x81101e00;   /* identity */
b[0x00c] = 0x81115200;   /* 暖肤色 */
b[0x00c] = 0x810fd100;   /* 风格化 */
```
**不需要改固件。** 相机实测无死机、无变砖，
LUT 是软状态（触屏/对焦后自动恢复）。

## 顺带修正了几个之前的错误结论

| 之前写的 | 实测结果 |
|---|---|
| "绝不写 EP 寄存器，写了只能拔电池" | ❌ 证伪。open 是零硬件初始化，写了画面会变 |
| "3D LUT 硬件未初始化" | ❌ OnOff 实测 = 1，**硬件是开着的** |
| "handle 墙不可破" | ⚠️ 只对厂商库成立，mmap 读写都能绕过去 |
| "`di-camera-app` import 里没有 3dlut，所以写入者在内核" | ❌ 库是**运行时 dlopen** 的，不在 import 表 |

**最贵的一课**：今天有 4 次"零结果"其实是工具失效导致的假阴性
（grep 零命中、busybox `ps` 只显示当前 tty、我臆断的内存保护、我臆断的"空闲区"）。
⇒ **任何"零结果"都必须先自证工具有效。**
