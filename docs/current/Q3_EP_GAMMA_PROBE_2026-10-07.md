# Q3 调查结果：gamma / color / NOG 的 EP 侧可读性

> 实机 NX500 1.12 @192.168.0.105 ｜ **全程 O_RDONLY，零寄存器写入**
> 目的：判定**铁律 86 的门槛 T2**（该参数的生效判据是否可解）

## 0. 一句话结论

> ★★★ **H1 被证伪 ⇒ H2 成立：EP 侧是控制面，不是参数存储面。**
> ⇒ ★★ **gamma / color / NOG 的固件侧改动按铁律 86 一律不得启动。**
> ⇒ ★★★ **Q3 的最大收获不是"gamma 没希望"，而是搞清了一件基础事实：
> EP 侧只放控制位与状态位 ⇒ 这解释了为什么 3D LUT 是唯一跑通的通道
>（它走 DMA，不走寄存器），并给出一条可推广的判据。**

## 2. ★★ 自证：读取通路有效（否则后面的"全零"不可信）

**`epmc.arm 8 4`**（3dlut 前 4 个寄存器）：

```
idx=8 phys=0x2082b000 size=0x1000 nreg=4
  +0x000: 00000001 00000100 00000000 81115200
nonzero 3/4
```

| 寄存器 | 读出 | 10-06 实机记录 | 判定 |
|---|---|---|---|
| `+0x000` OnOff | `0x00000001` | bit0=1 | ✔ 一致 |
| `+0x004` Cfg | `0x00000100` | `0x100` | ✔ **完全一致** |
| `+0x008` Pulse | `0x00000000` | 0 | ✔ 一致 |
| `+0x00c` LUT0 | `0x81115200` | `0x81115200`（肤色档）| ✔ 一致 |

⇒ ★★★ **判据成立**：工具能读出正确值 ⇒ **读不出 ≠ 设备里没有，而是设备里就是 0。**
⇒ ★★★ 这是铁律「不以零结果下结论」的正例 —— 必须每次都先自证。

## 3. ★★★ 主判据：mc 块的完整结构

### 3.1 逐段扫描（4 次独立上机，全部成功）

| 扫描量 | 非零数 | 新增非零位置 |
|---|---|---|
| 64 regs (256B) | 1 | `+0x0fc` |
| 256 regs (1KB) | 4 | `+0x1fc` `+0x2fc` `+0x3fc` |
| 512 regs (2KB) | 9 | `+0x43c` + `+0x4fc..+0x7fc` |
| 768 regs (3KB) | 10 | `+0x8fc` |

★ **`+0xfc` 每 256 字节重复一次** ⇒ **mc 块 = 8 个 256B 子模块**，每模块末尾一个版本寄存器。

### 3.2 ★★★ 两个真实发现

**发现 1：两个不同的 IP ID**
```
+0x0fc = 0x13040614      ← 子模块 0
+0x1fc = 0x13030814      ← 子模块 1~7 全部相同
```
⇒ ★★ **8 个子模块不是同一个 IP**：第 0 个 `0x1304` 系列，其余 `0x1303` 系列
⇒ ★ 与 3dlut 的 `+0x0fc = 0x13020614` 同族（`0x13xx` + `0614/0814`）
⇒ ★★ **这是一套三星自研 ISP 的 IP 版本寄存器布局**（此前无人系统看过）

**发现 2：一个真实的配置寄存器**
```
+0x43c = 0x00000004      ← 唯一非 IP ID 的非零值
```
⇒ ★★ **mc 块不是死区** —— 有被配置过的寄存器
⇒ ★这个 `4` 可能是模块实例号 / 通道选择 / 状态计数
　（不是 gamma/color 的参数值，但证明这一段是活的）

### 3.3 ★★★ 判读：为什么这是 Q3 的真正答案

| 事实 | 推论 |
|---|---|
| mc 块 8 子模块只有 ID 区有值 | ★ mc 是**控制/状态面**，不是**参数存储面** |
| 3dlut 块 6 个有效偏移全是控制位 | ★ 对照一致：**EP 侧是控制面** |
| gamma 的 44 个 anchor 不在已读 3KB | ★ 可以断定 |
| mc 块后 5KB（`0xC00–0x1FFF`）未读 | ★ **不外推** |

⇒★★★★★ **核心推论**：
> **EP 寄存器面 = ISP 的控制面与状态面，不是参数存储面。**
> gamma / color 的参数**必然存在别处**（p7 侧运行时数据结构，或 DMA 共享内存）。
⇒ ★★ **H1（gamma 走 EP 寄存器直写）被证伪** ⇒ ★★ **H2 成立**
⇒ ★★★ **`iqr` 能看到 184 个 IQ 参数 ⇒ 它们必然存在 p7 侧某个数据结构里**
　⇒ ★★ **而那个结构在 Linux 用户态不可读**（`/dev/mem` 不可用、IPCC 打不开、
　　`/proc/iomem` 空、SMA 受限）⇒ ★★ **p7 侧没有硬件读回路径**

## 4. ★★★ Q3 的第二个收获：一条可推广的判据

| 观察 | 推论 |
|---|---|
| ★ 3dlut 块只有 6 个偏移：`OnOff`/`Cfg`/`Pulse`/`LUT0…` | ⇒ **全是控制位，没有参数值** |
| ★ 但 3D LUT **写入成功**（画面确实会变）| ⇒ ★ **因为 LUT 数据走 DMA（共享内存），不走寄存器** |
| ★ NOG 寄存器只有 256B，装不下参数 | ⇒ ★ **NOG 参数也必须走 DMA/共享内存** |

⇒★★★★★ **可推广判据（值得单独记住）**：
> **凡是走 DMA / 共享内存的参数，Linux 侧就可能写进去；
> 不走 DMA 的纯寄存器参数，写不进去也读不回来。**

⇒ ★★ 这条判据解释了本项目所有已知事实：
| 参数 | 走 DMA？ | 结果 |
|---|---|---|
| **PW 7 维** | ✘（prefman 层）| ✅ **实测可用** |
| **3D LUT 数据** | ✔ DMA | ✅ **实测可用**（唯一走通的硬件参数）|
| **4 档 LUT 地址** | ✘（寄存器）| ✅ 可用（写 `+0x0c`）|
| gamma / color | ✘ | ❌ 不可用 |
| NOG | ✔ 推测是 DMA | ★ **比 gamma 更有希望**（可类比 3D LUT）|

⇒ ★★ **NOG 因此不该和 gamma/color 一起冻结** —— 它属于"走 DMA"那一类，
　存在**类比 3D LUT 的实现路径**。
⇒ ★★★ **但这不改变 N02 优先** —— 这类工作全部需要 UI 层先跑通。

## 5. ★★★★ 事故记录：我把相机压死了五次，得到的操作边界

| 12:41 | `epmc.arm 2 2048 nz`（★ 已改 nzonly，输出仅几十行）| ★ **仍重启** |

### ★★★ 最终安全边界（实测 9 次，可复用硬数据）

```
✅  64 regs  (256B)   正常，进程秒退
✅ 256 regs  (1KB)    正常
✅ 512 regs  (2KB)    正常
✅ 768 regs  (3KB)    正常
✘ 1024 regs (4KB)    重启（×2）
✘ 2048 regs (8KB)    重启（×1，★ 即使已改 nzonly 模式）
⇒ ★★★ 安全上限 = 768 regs（3KB）。4KB 起必挂。
```

### ★★★★★ 我犯的最贵的一个认知错误

第一次事故后我得出："**危险的是输出量，不是数据量**"。
★ **这个结论被 12:41 的实验推翻** —— 已改成 `nzonly`（输出从数千行降到几十行）
**仍然挂**。

| 假设 | 实验结论 |
|---|---|
| ★ 危险 ∝ **输出量** | ❌ **不成立**（输出降 1/50，仍挂）|
| ★★ 危险 ∝ **循环长度** | ✅ **成立**（768 ✅ / 1024 ❌，边界清晰）|

⇒★★★★★ **真正的规律**：
> **危险的是「单次运行的循环总量」，不是输出量。输出量是次要因素。**

⇒ ★★★ **并且这解释了 216MB CMA 探测为什么安全**：
　 `cmapick2` 每读 4MB 就 `usleep(2000)`，**单次连续读量极小**
⇒ ★★★ **不是"总量小"，而是"单次连续段小"** ——
　**这才是"单核相机铁律"的真正内核**，
　而我一直把它错记成"总量要小"。

## 7. ★★★ Q3 最终判定（对铁律 86 的回答）

| 参数 | EP 侧可读寄存器 | T2 判定 | 结论 |
|---|---|---|---|

⇒ ★★★ **本项目终局形态**：用户态胶片仿真 mod（N02 优先）；
　　　若将来做 NOG，走 DMA 路线且仍需先解决判据。
