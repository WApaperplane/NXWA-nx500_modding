# PW 属性 id 全图 —— R/G/B/HUE 破题（P3 / 2026-10-10）

> 结论：**已解，且比预期更直接** —— 不是 subcategory 链，而是 **8 个"内部变量 id"**（对应内部号 80–87 连续段）。

## 0. 一句话（★ 10-10 夜上机修订）

> **R/G/B/HUE 的内部 id 确为 `0x130` / `0x131` / `0x132` / `0x133`**（静态三层铁证，见 §1）——
> **但它们没有外部 MCB 通路**：上机 probe3 直推这四个 id，**rc=0 而 varlist 四维无任何变化**
> （scalar / color 两种编码皆然）；同一会话对照写 `0x110` → `PWSATURATION` 立即改变。
> 机制（离线铁证，见 §6）：外部 id 归一化器 `FUN_00051090` 的跳转表**只覆盖 `0x100–0x12e`**，
> 界外一律输出 `0xff` 并记日志后拒收 —— `0x130–0x133` 正落在界外。
> ⇒ **外部可达的 PW 直推 = 三维 SAT(0x110)/SHARP(0x111)/CON(0x112)（已实测回归 3/3）；
>    全 7 维进入 ISP 的唯一现成路 = 机身侧「画面向导 → 自定义1」**
>    （该路径由内侧档位应用函数直接发内部 id，绕过归一化）。
> 打通外部 R/G/B/HUE 的唯一技术路 = **改 p7**（扩跳转表边界 + 补映射）⇒ 属 **A1（需 G4）**。

> 10-09 夜盲试失败的原因与此无关（那次是**从未覆盖该段**：盲试上限 0x114、白名单上限 0x12b）。

## 1. 完整 id 映射（三层证据，全部静态铁证）

### 1.1 第一层：p7 权威分发表 —— `FUN_000d6bac`（id → 变量名 + 内部号）

- **机制**：`movw r3,#0x13e; cmp r1,r3; ldrls pc,[pc,r1,lsl#2]` —— **0..0x13e 全空间跳转表**（@0xd6bcc，319 项）。
- **case 体**（0xd73b0–0xd7660）：`strh N,[r2]; ldr r3,[pc,..]; str r3,[r0,#8]` —— 输出 **内部号 N** + **变量名字符串指针**。

| id | 内部号 | 变量名（case 体内字符串指针，铁证） |
|---|---|---|
| 0x10e | **80** | VARIABLE_PWCOLOR（聚合） |
| **0x10f** | **85** | VARIABLE_PWSATURATION |
| **0x110** | **86** | VARIABLE_PWSHARPNESS |
| **0x111** | **87** | VARIABLE_PWCONTRAST |
| **0x130** | **81** | **VARIABLE_PWCOLOR_R** ★ |
| **0x131** | **82** | **VARIABLE_PWCOLOR_G** ★ |
| **0x132** | **83** | **VARIABLE_PWCOLOR_B** ★ |
| **0x133** | **84** | **VARIABLE_PWHUE** ★ |

★ **内部号 80–87 连续 8 连号** = PWCOLOR(聚合) + R/G/B/HUE + SAT/SHARP/CON —— PW 全家族到齐。

### 1.2 第二层：档位应用序列（行为铁证）—— `0x51b20` 区函数

依次发送 8 项（每项 `bl FUN_000d6b20(this, id, &v, 4)`，其中 FUN_000d6b20 = "变量发送器"）：

| 序 | 发送 id | 值来源槽 | 对照 §1.1 |
|---|---|---|---|
| 1 | 0x10e | 219 | PWCOLOR |
| 2 | **0x130** | 220 | PWCOLOR_R |
| 3 | **0x131** | 221 | PWCOLOR_G |
| 4 | **0x132** | 222 | PWCOLOR_B |
| 5 | **0x133** | 223 | PWHUE |
| 6 | 0x10f | 224 | PWSATURATION |
| 7 | 0x110 | 225 | PWSHARPNESS |
| 8 | 0x111 | 226 | PWCONTRAST |

⇒ **两套独立证据（分发表 + 应用序列）逐项一致**。

### 1.3 第三层：外部→内部归一化 —— `FUN_00051090`（解释历史"一位偏移"）

| 外部 id | → 内部 | 变量 | 实测对照（10-09 夜） |
|---|---|---|---|
| 0x10f | → 0x10e | PWCOLOR(聚合) | ✓ "0x10f 写 PWCOLOR 相关（[14]）" |
| **0x110** | → **0x10f** | PWSATURATION | ✓ 实测"0x110 = SAT" |
| **0x111** | → **0x110** | PWSHARPNESS | ✓ 实测"0x111 = SHARP" |
| **0x112** | → **0x111** | PWCONTRAST | ✓ 实测"0x112 = CON" |

⇒ **4/4 与实测吻合**。**这就是"0x110 表现为写 SAT"的原因——它被 p7 归一化到内部 0x10f**。
（也解释了 0x112 为何不在分发表：它是"外部编码"，经归一化后落在内部 0x111。）

## 2. 副产品：官方值编码 LUT（对 P2 的第三方交叉验证）

```
0xFF6FD80A 0xFF7FD80A 0xFF8FD80A … 0x005FD80A 0x006FD80A（值 0..16）
```

⇒ P2 的编码修复获得**官方静态表**的第三方验证（此前只有实测对照）。

## 6. ★★ 机制铁证：为什么外部够不到 0x130–0x133（10-10 夜新增）

外部 setter 入口（唯一）：
```c
FUN_0004ccf4(ext_id, val, sz):              // 属性总线 → 变量
    iVar1 = FUN_00051090(ext_id, &conv);
    if (iVar1 == 0) FUN_000d6b20(conv, val, sz);
    else { 记日志(行 0x31b); return -1; }   // 归一化失败 → 拒收
```
`FUN_00051090`（file off 0x51090，108 B）：
```
sub  r3, r0, #0x100          ; r3 = ext_id - 0x100
cmp  r3, #0x2e               ; 合法域 = 0x100..0x12e（47 个）
ldrls pc, [pc, r3, lsl #2]   ; 跳转表 @0x510b4（47 项）
b    0x51394                 ; 越界 → 拒收（mov r3,#0xff; str r3,[r1]; ...）
```

`FUN_000d6b20`（真·变量发送器）全部调用者（全伪代码 grep）：
* **外部侧**：只有 `FUN_0004ccf4` / `FUN_0004cde0`，其调用 id 全部 ≤ 0x12e
  （0x100/0x101/0x104/0x105/0x106/0x10a/0x10d/0x10f/0x110/0x111/0x112/0x117 …）；
* **机身侧**：**只有档位应用函数（0x51b20 区，伪代码行 34138–34210）**，直接发内部 id
  `0x10e, 0x130, 0x131, 0x132, 0x133, 0x10f, 0x110, 0x111`，值取自 `FUN_00063eb4(0xdb..0xe2)`
  （参数槽 219–226）。

⇒ **R/G/B/HUE 只能由机身侧档位应用写入**（= 官方「画面向导 → 自定义1」触发）。
外部要够到，必须改 p7（扩跳转表边界 + 补 handler）⇒ **A1 / G4**。
