## 0. 一句话结论

**"外部变量写"与"档位应用"在 p7 侧的调用形态【完全同构】**（同锁 `0xd69cc`、同对象 `0x8142ab20`、同发送器 `d6b20`、同编码量级）——
此前设想的"缺事务/缺对象/编码不同"**全部不成立**。差异仅剩 3 个具体点（§3）。
而"画面生效"的最后一步在**"档位池（参数槽 0xda..0xe2）"**上：**档位应用读池→编码→发送**；
外部写**没有经过池、也没有"应用"这一步**。⇒ **A2 = 让外部写真正"写进档位池并触发应用"**。

## 1. 机制全图（全部为本次反汇编实证）

```
【外部写】（pw_direct / pwsend —— 现况：写变量表，画面不变）
  Linux ──SetVariableDataMCB(id|0x1300)──▶ p7
    └─ FUN_00051090 归一化（A1 放行 0x130-0x133；域外拒收）
    └─ FUN_0004ccf4 包装：bl 0xd69cc（锁）→ FUN_000d6b20(obj, conv, &val, sz)
    └─ FUN_000d6b20：ldr r0,[obj,#4] → FUN_00071cf8
         └─ FUN_00071cf8：按 (id>>8)∈{0,1} 选子对象 → 虚调用 vtable[5]
              └─ [运行时对象方法] → 写"变量存储"（varlist 可见）
  ⇒ 结果：varlist 变；【画面不变】

【档位应用】（"向导→自定义1"的等价物 —— 画面真正生效）
  触发：参数槽（0xda..0xe2）变更事件 → FUN_00053330(selector) 通知器
    └─ 跳表 selector 0xda..0xe2 → 0x545b8 → FUN_00051ab8
  FUN_00051ab8（"应用"本体，~340B）：
    ① 读槽 0xda（风格 v0-13）→ FUN_000d6afc(20, 风格值)   ← ★ 外部写没有
    ② 读槽 0xdb → 编码 → d6b20(0x10e, ...)                 ← ★ 外部写没有
    ③ 读槽 0xdc..0xe2 → 各自编码 → d6b20(0x130..0x133, 0x10f..0x111)
       （每项前都 bl 0xd69cc 取锁——与外部写相同）
  ⇒ 结果：varlist 变 + 【画面变】

【槽存储结构】（"档位池"在哪）
  访问器 FUN_00061aec(slot)：536 项跳表 → 逐槽"地址解析函数"（0x638xx 群）
    模式：r0 = [0x80062e90]（运行时基址指针）+ 固定偏移
  槽 0xda..0xe2 → 偏移 0x170..0x190（9 × 4B 连续区）
  读槽 FUN_00063eb4(slot) = [访问器(slot)]（slot==0xcf 时取高字节特判）
  写槽 FUN_00064f0c(slot, val) = *访问器(slot) = val     ← 极简：一条 str
```

**注**：槽存储基址 `[0x80062e90]` 为**运行时值**（p7 私有 RAM）——外部（Linux）不可直达，与"p7 LUT 缓冲读不到"同理 ⇒ **"外部写池"必须走"调用"（补丁）**。

## 4. 槽编码表（档位应用"读槽→发送"）

| 槽 | 目标 id | 编码 |
|---|---|---|
| 0xda | —（风格） | v(0-13) → 查表得 0x14xxxx 风格值 → `d6afc(20, 值)` |
| 0xdb | `0x10e` | `(v*360+360)>>8`（近似；负/零有特判）——**待细核** |
| 0xdc | `0x130`(R) | `((v*255/200)<<20) \| 0xff` |
| 0xdd | `0x131`(G) | 同上 |
| 0xde | `0x132`(B) | 同上 |
| 0xdf | `0x133`(HUE) | `LUT[0x8056d848][min(v,20)]`（SCALAR：`(raw16<<16)\|0xd80a`；v>20→0x000d80a?） |
| 0xe0 | `0x10f`(SAT) | 同上 LUT |
| 0xe1 | `0x110`(SHARP) | 同上 |
| 0xe2 | `0x111`(CON) | 同上 |

**LUT 表** `0x8056d848`（= `[0x80051e38]` + 0x220）—— 可直接从固件读取（0-20 → 32-bit 编码值）。

## 5. A2 方案骨架（待设计细化）

**目标**：外部一条命令（如 `filmlab.sh pwslots ...`）→ **写 8 槽 + 触发应用** → **画面即变（无需向导）**。

| 组件 | 设计 |
|---|---|
| **靶点** | `0x4ccf4` 的 `bl 0xd6b20`（偏移 `+0x3C`，指令 `eb02277a`）**改道特判块**（沿用 A1 的"重定向+特判块"技术，已跑通） |
| **特判块** | 对"新 id 族"（候选 `0x140-0x148` = 槽 0xda..0xe2 直写命令；或复用 0x130-0x133 升级语义）：`bl 0x64f0c(slot, val)`（写槽）→ 写完 8 槽后 `bl 0x545b8`（触发应用）→ 返回 0；其余 id 跳回原 d6b20 |
| **值语义** | 外部按"**槽值域**"发送：R/G/B ≈ 0-200（配方值直用）；SCALAR（HUE/SAT/SHARP/CON）= 0-20；触发命令（值=1） |
| **触发策略** | ②选一：a) 依赖"写槽=隐式触发"（**待验证对 64f0c 直调是否成立**——64f0c 本身无通知调用）；b) 显式 `bl 0x545b8`（**稳妥**） |
| **0xd6afc 补否** | 若实测"应用后画面仍不全对"，特判块补 `bl 0xd6afc(20, 风格值_from_0xda)` |
| **filmlab 端** | 编码器改"槽值域"（`pw_slot_code`）；apply ③ 改为"8 槽直写 + 触发" |
| **持久化** | apply 保留 `prefman save`（Linux 侧，重启回退已处理） |
| **验证** | ① QEMU 真字节套件（同 A1：模拟调用链 + stub 64f0c/545b8）② 灰度上机（用户盯画面） |
