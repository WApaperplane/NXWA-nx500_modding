# P4 结案：3DLUT 硬件窗口"两态之谜"（2026-10-11 深化）

> 承接 `U6_ONMACHINE_RESULT_2026-10-09.md` §4.3（P4 初归档）。
> 本文 = 离线四层证据链（p7 / Linux 用户态 / 用户态驱动库 / 内核）终版结论。
> 工具：`tools/nx-fw/scan_mmio.py`（本轮新增）；环境：WSL NXKS2。

## 0. 结论（一句话）

**dump 中"生效态 +0x014+ 区（58×u32=0x10 × 16 单元）"与"16 处地址镜像"是 3DLUT 硬件块
（物理 `0x2082b000`–`0x2082bfff`，**4KB**）的硬件内部状态**：
全部软件面（p7 固件 + Linux 全部相关二进制）对该窗口只写 **5 个寄存器 `{+0x00,+0x04,+0x08,+0x0c,+0x10}`**，
`+0x014+` 与 16 镜像区**无任何软件写入路径**；该区由硬件在"装载动作"（Acc pulse）后填充、复位/重配（op_init）后清零。

**窗口 4KB = 16 单元 × 256B** —— 由内核（chunk-02）设备资源表权威确认（本轮新证据）。

## 1. 证据链（四层）

### 1.1 p7 固件——字节级穷举（scan_mmio.py，5 种寻址形态）

- `0x2082b000` 基址构造点 = **11 处，全部在 `0x4cf3d4`–`0x4cf4d0`**（已知 LUT 原语组）
- 该组访问偏移集合 = **恰为 `{+0,+4,+8,+c,+10}`**（objdump 逐条复核）
- `+0x014+` / `+0x10c..+0xf0c` 写入 = **0 处**；字面量池常量 = 0 处
- **对照组**：邻块 `0x20827000`（20+ 构造点）偏移集合达 `+0x14..+0x4c` —— 证明扫描法能发现 +0x14+ 偏移
- 邻块 `0x2082a000`：13 构造点（`0x4a6dxx`；64B 描述符搬移 + 7-case 配置）

### 1.2 Linux 用户态 6 二进制——全扫描

libudd5.so / di-camera-app / libmulticore-bridge / libshell-command / mcbtest / st：
对 `[0x2082a000,0x2082d000)` 的常量构造 = **全线 0**
（合理：用户态经 mmap 后全用运行时虚拟地址。）

### 1.3 libudd5.so——通路完整解密（`/usr/lib/libudd5.so`，320KB，stripped）

**初始化链**：`d5_ep_open → d5_udd_open("/dev/drime5_ep") → sub_1b458(fd)`：
`ioctl(fd, 0x80506864, &info)` 取 **80B 寄存器区域表（10 组 {start,end}）** →
`mmap ×10–12` → 写各模块 `*_reg_base`（**`ep_3dlut_reg_base` 赋值点 = `0x1b7d8`**，BSS `0x57730`）。

**reg 函数组**（源码级还原）：OnOff/SelCbCr_ch/SelLUT/SetColorFormat_LUT0/1/Acc_OnOff/rw_Start/SetAddress
—— 偏移集合 **`{+0,+4,+8,+c,+10}`**，与 p7 **完全同构**。
`d5_ep_mmap @ 0xc02cd32c`（内核侧）= `remap_pfn_range` 直接映射物理页。

### 1.4 内核（chunk-02）——设备资源表（权威）

**认知修正**：3DLUT 驱动不在 rootfs 的 .ko 里（rootfs 仅 Wi-Fi/蓝牙 4 模块），
`drime5_ep`/`d5_ipcc`/`d5_sma`/`d5_lock` **编译在内核内**。
链：chunk-02 → zImage → gzip@0x5580 → vmlinux（7.47MB）→ **vmlinux-to-elf（37,167 符号）**。

| 关键点 | 地址 | 内容 |
|---|---|---|
| `drime5_ep_ioctl` | `0xc02cd37c` | cmd type=0x68 家族分派 |
| 0x80506864 分支 | `0xc02cd798` | → `ep_get_reg_info` |
| **`ep_get_reg_info`** | `0xc02cc4d4` | **`memcpy(buf, 0xc07551c8, 80)`**（10×{start,end}） |

**设备资源表**（vmlinux 偏移 `0x6f31a8`，28B/条）：

| # | 物理区间 | 大小 |
|---|---|---|
| 1 | 0x20820000–0x20821bff | 0x1C00 |
| 2–7 | 0x20823000 / 0x20824000 / 0x20826000 / 0x20827000 / 0x20828000 / 0x20829000 各段 | 0x1000–0x2000 |
| 8 | 0x2082a000–0x2082afff | 0x1000 |
| **9** | **0x2082b000–0x2082bfff（3DLUT）** | **0x1000** |
| 10 | 0x20821c00–0x20821cff | 0x100 |

⇒ **3DLUT 窗口 = 4KB 权威确认** ⇒ "16 单元 × 0x100" = 完整窗口 ✓
⇒ 邻块 8（0x2082a000）= p7 `0x4a6xxx` 操作对象（同 4KB）

## 2. 结论修正（相对 U6 §4.3）

| 项 | 原表述 | 修正 |
|---|---|---|
| +0x014+ 区性质 | "H-P4a：装载配置模板/描述符残留" | **硬件块内部状态区**（三软件面穷举无写入；装载后自填充、复位自清零） |
| 16 单元 × 0x100 | dump 解析推断 | **内核资源表确认窗口 4KB**（16×256B 即全窗） |
| 16 处镜像 | 现象 | 写 `+0x0c` 单点 → 硬件广播至 `+0x0c + k×0x100 (k=0..15)`；软件只写单点（已证） |

**可证伪条件**：出现任何"对 `0x2082b014..0x2082b0f8` / `0x2082b10c..0x2082bf0c` 的软件写"——
须逃过本轮 5 类寻址扫描（字面量池/MOVW/MOV/MOVT/GOT 间接）+ 运行时指针分析。

**认知修订**：
1. 3DLUT 完整软件栈 = `工具 → libudd5.so → /dev/drime5_ep（内核）→ mmap`；
   `0x80506864` ioctl = "取寄存器区域表"。
2. **p7 与 Linux 侧写同一硬件窗口、同一 5 寄存器集** —— 双主竞争面收敛为 5 寄存器 + Pulse 时序。
3. 内核三件 build 不同（#150 Jul15 / #7 Jun3 / #1183 Jun4）；**仅 chunk-02 含完整 ep/ipcc/sma 栈**。

## 5. 方法论备忘

1. p7 用小立即数 `mov #0xb000; movt #0x2082`（MOV 0x3A 家族）——**grep '0x2082b' 必漏**，须 5 分类扫描。
2. Linux 用户态搜不到物理地址常量（mmap 后是虚拟地址）——须追驱动库初始化链。
3. NX500 的 EP 栈编译进内核（chunk-02）；`vmlinux-to-elf` 3 秒恢复 3.7 万符号。
4. `0x80506864` 编码为 `movw #0x6864; movt #0x8050` —— 字节搜 `64 68 50 80` 无效。
