## 2. R2b：一项标签替换 — 设计 + 实物样本

### 2.1 工艺族（三条）

| 工艺 | 机制 | 字节量 | 适用 | 实例 |
|---|---|---|---|---|
| **1. 等长字符串替换** | 原地改写字符串部分字节（长度不变） | 1–N 字节 | ASCII 文本、等长中文对 | 样本 A（1 字节）|
| **2. 指针替换** | 改表记录的指针字段，指向另一既有字符串 | 4 字节 | 任意长度差异；目标必须已存在 | 样本 B（4 字节）|
| 3. 不等长文本（中文） | 缩短 ⇒ `\0` 填充；加长 ⇒ 工艺 2（指针指向新串，新串放补丁体附加区/复用零区） | 组合 | 第二阶段（目标标签定位后）| 待定 |

**「中文不截断」约束**（工艺 3）：中文为多字节编码（UTF-8），替换串必须整体处理边界；禁止从多字节字符中间截断。原厂 edje/OSD 文本的字体系列约束参见 `D7_NXFILMUI_CJK_REBROADCAST_2026-10-08.md`（mod 自制渲染的 CJK 经验；原厂文本以目标定位后的实测为准）。

### 2.2 实物样本（已制作 + 离线验证 ✅）

样本规格：`fw/v1.12/dicam/r2b_str_replace_samples.json`。离线应用复验结果（2026-10-15）：

| 样本 | 补丁点 | old → new | 效果 | 净差 |
|---|---|---|---|---|
| **A**（等长） | file `0x3D099C` / VA `0x3D899C` | `31`(‘1’) → `32`(‘2’) | CUSTOM1 图标串 → `...custom02.png`；**表①②两消费面同步变化**（共引同串） | 1 B |
| **B**（指针） | file `0x40D170` / VA `0x415170` | `74893d00` → `30763d00` | 表① CUSTOM1 icon 指针 → `smart_filter/icon_sf_off.png`（跨组可见变化） | 2 B |

- **精确匹配原字节** ✅：两样本均先断言 old 字节再应用（脚本内置 assert；见复现命令）。
- **与 C-2 无冲突** ✅：补丁点与 `0x3656DC`/`0xC23A8` 无重叠（实测）。
- **可恢复** ✅：old 字节已知，逆写即可；或恢复官方件（md5 `ae44293e…`）。
- **不改变参数** ✅：A/B 均只动「显示字符/指针」，不触碰任何参数值、id 或行为逻辑。
- 复现（PC）：

```bash
python - <<'PY'
import struct
d = bytearray(open('E:/NXWA/fw/v1.12/extract/di-camera-app/com.samsung.di-camera-app/bin/di-camera-app','rb').read())
assert d[0x3D099C] == 0x31; d[0x3D099C] = 0x32
assert bytes(d[0x40D170:0x40D174]) == struct.pack('<I',0x3D8974)
d[0x40D170:0x40D174] = struct.pack('<I',0x3D7630)
open('/tmp/di-camera-app.r2b-demo','wb').write(bytes(d)); print('OK')
PY
```

## 3. R3a：投递设计（对齐 §5 全部条件）

### 3.1 设计要素

| 要素 | 设计 | 依据 |
|---|---|---|
| **版本检查** | 操作前校验目标 md5 == `ae44293e…`（匹配样本才允许）；变体登记见 UI-R0 §2 | UI-R0 §7 |
| **禁用** | 补丁体不存在 ⇒ 不挂载/不生效（T2 条件挂载语义）；本实验包**不加载代码** ⇒ 无「载入前禁用标记」负担 | T2_DELIVERY_REVISION §2 |
| **隔离** | 失败 = umount（挂载层）或逆写（字节层）立即恢复；与 C-2 共存：字节无重叠，可合成同一补丁体 | 本文 §2.2 |
| **恢复** | ① 逆写 old 字节；② umount 回官方件；③ 重刷官方 SLP（兜底） | 既有三路 |
| **验证时机** | 正常关机开机（自然加载）；**禁 restart**（10-13 实测卡死）；生效路径三候选（a/b/c）见 `T2_DELIVERY_REVISION_2026-10-15.md` §3 | 同左 |
| **合成补丁体** | 以 C-2 v2 补丁体为基 → 追加 R2b 补丁 → 新补丁体（md5 登记）；或独立（两组补丁互不依赖） | 本包实测 |

### 3.2 §5 五问逐条回答（对照 `NATIVE_UI_ROADMAP` §5）

| # | 问题 | 本设计回答 |
|---|---|---|
| 1 | App 首次 exec 前，p14/宿主/库可读？休眠跳过 exec？ | **不适用**（不加载宿主/代码）；数据替换的唯一时序问题 = 「文件何时被加载」——由投递路径（a/b/c）决定，见 T2_DELIVERY_REVISION |
| 2 | 禁用标记在代码载入前可判？ | **不适用**（无代码载入）；等价物 = 「补丁体存在性」（T2 挂载条件，已有） |
| 3 | 缺库/坏哈希/版本不匹配/上次未完成启动 → 回原厂？ | 版本检查 = md5 gate（§3.1）；哈希不符 ⇒ 不操作；恢复 = umount/逆写 |
| 4 | 拔 SD/断网/缺配置能否开机？ | ✅ 能——补丁体在 p14（机内），不依赖 SD/网络；挂载点坏值场景 = 文件缺失即不挂（条件逻辑） |
| 5 | 失败后在机身不联网时能否撤销？ | ✅ 能——逆写（相机端 shell）或 umount；均在机内完成 |

### 3.3 风险注解

- 本包风险等级 = **低**（对比：C-2 桩 = 中、宿主 .so = 高、p7 = 高）。
- 失效模式：图标不显示/显示错位（最坏）——不影响拍摄、不影响参数、不崩（字符串级）。
- ⚠ 保留纪律：**禁 restart**；写机前跑门控；上机时先采负载基线。
