## 0. 结论

1. **记录 ABI = 固定 0x114 字节 × N 条**，字段 `[icon VA ptr, id int, name VA ptr, 264B 零填充]`；**无计数/哨兵字段**——数量由消费点常量或调用参数给出（14 = PW 域）。
2. **两份副本不是「同一表两处拷贝」**：表①（file `0x40C6A8`）= OSD 面（`Draw_pw` 直接读 .rodata）；表②（file `0x41754C`）= Smart Panel 面（`GetButtonInfo` 装载到 .bss 工作副本 `0x596EE4`）。**旧表述「另一 UI 面副本」修正为此**。
3. 字符串（icon 路径 / 内部名 / MSG 名）均为**静态 .rodata**，无动态分配证据 ⇒ 文本生命周期 = 进程级常驻，无释放问题。
4. 线程要求：**UI 线程内调用** 🔶（函数均为视图绘制/更新族；未在静态中取得线程绑定证据 ❓）。
5. 写入规则（供 R2b/R3a 直接引用）：见 §5——**不改 id 字段、字符串等长替换、name 目标必须在解析链内**。

## 1. 记录 ABI（表）

| 项 | 值 | 证据 |
|---|---|---|
| 记录大小 | **0x114（276 B）固定** | `Draw_pw` 步进 `puVar3 += 0x45`（词）；`GetButtonInfo` `memcpy(..., 0x114×N)`（0xF18=14、0x9B4=9、0x228=2、0x33C=3、0x450=4、0x1D1C=27 等，全部整除）✅ |
| 字段 0 | `+0x00` icon 路径字符串指针（VA） | 转储注解 + `Draw_pw` 取 `[iVar4*0x45]` 送 `osd_set_image` ✅ |
| 字段 1 | `+0x04` 槽位 id（int，0=OFF…13=PRO） | 转储逐条 + `Draw_pw` 比较 `puVar3[0x46]`（=记录+0x04）✅ |
| 字段 2 | `+0x08` 名称字符串指针（VA，内部名） | 转储（`CAP_MENU_CUSTOM_MODE_1` 等）✅ |
| 尾部 | `+0x0C..0x113` 零填充（264 B） | 转储「66 zero words skipped」✅ |
| 对齐/字节序 | 4B 对齐 / LE32 | 全体地址 4 对齐；全项目 LE ✅ |
| **条目计数** | **无显式 count/sentinel 字段**；数量随消费点：`Draw_pw` 硬编码上限 `0xE`；`GetButtonInfo` 的 `memcpy` 长度与返回值 `iVar6` 携带 N | 反编译 ✅ |
| **终止条件** | 遍历以常量 14 封顶（`while (iVar4 != 0xe)`）；无哨兵条目 | 反编译 ✅ |
| 「无」态约定 | `id==0`（OFF）充当空态：`iVar1==0` 时**跳过遍历**直接取记录 0 | `Draw_pw` ✅ |
| 值域 | id ∈ {0..13}（值源 = `User_Spec` 0xda）；**遍历不命中 ⇒ 图标置 0（清空）** | `Draw_pw` 链 ✅ |
| 表总大小 | 表①/②各 14×0x114 = **0xF18**（与 `memcpy` 0xF18 互证） | ✅ |

## 2. 两副本区分（修正旧口径）

| 副本 | file | VA | 消费方 | 顺序 | 语义 |
|---|---|---|---|---|---|
| **表①** | `0x40C6A8` | `0x4146A8` | `CAPPGUICustomView::Draw_pw`（OSD 图标） | 原始序（非 id 序） | **OSD 指示面** |

## 5. 写入安全规则（写死，供 R2b/R3a 引用）

1. **只在匹配样本上写**（md5 == `ae44293e969101d1cf0a93cbe9b99f75`；见 UI-R0 §7）。
2. **不改 id 字段（`+0x04`）**——会破坏「值↔条目」匹配。
3. **字符串替换保持等长**（icon 路径/内部名，禁截断——等长改写或改指针）。
4. **改 name 指针时**，目标名必须在 `GetDescriptionByTitle` 链内（否则文案异常/为空——见 R1A §3）。
5. **改动全部可逆**：保留原字节（bytepatch 规格化）。
6. 表②的 .bss 副本（`0x596EE4`）**暂不触碰**（消费者未解，见 R1A U2）。
