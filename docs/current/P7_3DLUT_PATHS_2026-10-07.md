## 六、★★★★ DIOSAL 事件框架（本次更正一处误判）

`FUN_004db91c` / `FUN_004dba00` / `FUN_004dbb08` 曾被推测为"参数块注册/读写"。**实测字符串证明它们是 DIOSAL 事件标志 API**：

```
FUN_004db91c  →  "_fx_eventflag_send"      (发送)
FUN_004dba00  →  "_fx_eventflag_receive"   (接收)
FUN_004dbb08  →  "_fx_eventflag_clear"     (清除)
错误日志格式： 'DIOSAL' + 'param error:%s  %s:%s:%d\n' + 'error:%s  %s:%s:%d:%d\n'
```

- 全固件 **389 处**调用，第 3 参数是**源码行号**（`0x135 / 0x7e / 0x288 / 399 ...`），用于日志 `file:line`。
- `CBackend_3dlut_Base::_OnLoad`（vtable 槽 `+0x94` = `FUN_0011cf04`）里有：
  ```c
  FUN_004db91c(0x807148f4, 0x805836e8, 0x300, &DAT_81433cc8, 2);
  //           "product/Backend/EP/3DLUT/CBackend_3dlut_Base.cpp", "_OnLoad",
  //           0x300 = 768, &DAT_81433cc8 = 运行时 BSS 缓冲, 2
  ```
  ⇒ ★★ **发送一个 768 字节的事件消息**，缓冲 `DAT_81433cc8` 位于运行时 BSS（超出镜像 0xC40000 ⇒ 初值不可见）。
  ⇒ **768 = 0x300 = 3 × 256**，与 3DLUT 寄存器块的 256B 粒度吻合。

## 七、★★★★ 回答用户的两个问题

### 7.1 「LUT 写入对拍摄照片有没有实际效果？」

**答：有，但必须挂对路径（Still）。我此前的实验挂的是 View。**

| 你做的操作 | 影响的路径 | 取景器 | 拍摄照片 |
|---|---|---|---|
| 改 3DLUT 寄存器 `+0x0c` 指向自己的 CMA | View 的地址被换 | ★ 花屏 | ✘ **不变** |
| 走 `View::_load`（消息 `0x10000002`） | View | 变化 | ✘ 不变 |
| 走 `Still::_load`（消息 `0x20000002`） | Still | 不变 | ★ **变化** |
| 4 档内置切换（`DAT_003837f0~fc`） | View | 变化 | ⚠️ **部分地址两路共用 ⇒ 可能同时变** |

⇒ ★★★ **要验证"照片是否受影响"，必须显式驱动 `Still` 路径**
　（消息 ID `0x20000002`，或调用 `FUN_0011e678` / 其 vtable 槽 `0x58390C`）。

### 7.2 「LUT 花屏问题」

**根因不变（表格式未知），但本次否证两条旧线索 + 明确了通道结构：**

```
✔ 通道数 = 3、格式数 = 2（FUN_004a5b6c 硬校验）
✔ 表地址池步长 = 0x4D00（槽位大小，非元素大小）
✔ 硬件只写 5 个寄存器（使能 + 双地址），绝无尺寸 ⇒ 长度硬编码在 DMA 控制器
✘ "lut size error 3360 是 3DLUT 上限"  → 否证（是 XTC/CS 表）
✘ "取景器与拍照共用同一 3DLUT 状态"    → 否证（两条独立路径）
🔶 每节点 4 字节内部布局 —— 仍未定（受 7.2 天花板限制）
```

| **116** | ★★★★★ **「某功能的字符串线索」必须验证字符串的 rodata 聚类**。`lut size error` 与 `ipc_cs_adj` 在同一块、同一源文件 ⇒ 属 XTC 表，不属 3DLUT。**孤立看字符串名会误归。** |
| **117** | ★★★★★ **C++ 固件要按 RTTI + vtable 解，不要按"字符串交叉引用"解**。`View::_load`/`Still::_load` 是虚函数，**没有直接调用者**（全走 `(**(code**)(*obj+off))()`），字符串 xref 恒为空。 |
| **118** | ★★★★ **同一个硬件块（3DLUT）可被多条互不共享状态的软件路径驱动**。「改了硬件 = 所有功能都变」是错的，必须按**消息 ID + 表地址选择器**区分路径。 |
| **119** | ★★★★★ **C/C++ 参数里的"疑似长度/ID"必须先解出该参数在函数里的用途**。`0xb4/0x98` 我一度当成描述符长度，实为 **DIOSAL 错误日志的行号**。**同名形参不等于同语义。** |
| **120** | ★★★★ **判定"寄存器里没有 X 字段"必须做全镜像 grep 该寄存器块**，不能只看一个函数。本次 grep `0x2082b` 全部命中 = 5 个寄存器，才敢下"绝无尺寸字段"。 |
