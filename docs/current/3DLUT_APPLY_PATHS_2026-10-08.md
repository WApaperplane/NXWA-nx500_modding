## 0. ★ 五条一句话结论

1. **全镜像只有 7 个函数访问 3D LUT 寄存器块 `0x2082b000`**（穷举证据见 §1）——都是 40 字节以内的寄存器原语。
2. **唯一把表地址交给硬件的函数 = `FUN_004a5e30`**；`FUN_004a5c44`(Load) 与 `FUN_00179384`(Save) 是它的两个封装。
3. **5 条应用线路**：`View`｜`Still`｜`CS`｜`Base`｜**`MCB`（本次新发现）**。
   前四条是 C++ 虚方法（无 BL 调用者，走 vtable），第五条是 MCB 生产域的**打包序列**。
4. ★★ **寄存器语义修正**：`+0x00c` / `+0x010` **不是 LUT0/LUT1 两条通道**，而是
   **Load 目标地址 / Save 目标地址**；`+0x008` 的 **bit8 = Load 启动脉冲 / bit4 = Save 启动脉冲**（先置后清）。
5. ★★ **存在第二套表缓冲池**：View 档位池 `0x810FD100` 族之外，MCB 线路用
   `0x813D8800 / 0x813DD500 / 0x813E2200 / 0x813E6F00`（QEMU 实测逐条命中），**步长同为 `0x4D00`**。

## 1. L0 — 硬件入口穷举（为什么只能有 7 个）

p7 用 **`mov Rd,#imm12(rot)` + `movt Rd,#imm16`** 构造 MMIO 基址（**不是 movw，也不在字面量池**），
所以按寻常"搜 0x2082b000 字面量"会得到 0 命中（旧文档的盲区）。按指令位模式扫描后：

```
L0. 构造 0x2082b000 的位置 → 全部 7 个函数
   FUN_004cf3d4   OnOff            (+0x000 bit0)
   FUN_004cf3fc   Cfg[1:0]         (+0x004) SelCbCr_ch
   FUN_004cf414   Cfg[5:4]         (+0x004) SelLUT（值 = 通道号 0/1/2）
   FUN_004cf42c   Cfg[8]           (+0x004) ch0 使能
   FUN_004cf444   Cfg[12]          (+0x004) ch1 使能
   FUN_004cf45c   Pulse bit0       (+0x008) Acc 使能
   FUN_004cf484   ★ Pulse bit8/bit4(+0x008) **Load/Save 启动脉冲（先置后清）**
   （FUN_004cf4b4 用条件执行 `streq/strne`，按偏移写 +0x00c/+0x010，不构造基址）
```

⇒ **不存在"绕过这 7 个原语直接写 3D LUT 硬件"的代码路径**（判据：全镜像常量构造穷举）。

> ★ 与旧文档的差异：旧文只列了 5 个寄存器偏移，且把 `+0x008` 记作 "Pulse=0（无意义）"。
> 本次解出 **bit8/bit4 是启动脉冲** —— 它才是"把表推给硬件"的动作。

## 2. L1/L2 — 分发层（6 个函数）

| 函数 | 作用 | 写什么 |
|---|---|---|
| `FUN_004a5e10` | mode==1 时**关闭** | `OnOff(0)` |
| **`FUN_004a5e30`** | ★ load/save 主体（**唯一写表地址**） | OnOff、Acc、**表地址**、Cfg、启动脉冲 |
| `FUN_004a5ff0` | 配置通道使能与选择（**不搬数据**） | Cfg 位 + ch 使能 |
| `FUN_004a5b6c` | 描述符解析 → `FUN_004a5ff0` | 同上 |
| `FUN_004a5c44` | **Load** 3 参封装 → `FUN_004a5e30` | 写 `+0x00c` + bit8 脉冲 |
| `FUN_004a5de4` | ch 使能写入器（mode 1/0/2） | `FUN_004cf42c/444` |

**p7 侧 API 对**（`0x179xxx` 区）：

| API | 底层 | 模式（QEMU 实测） | 锁 |
|---|---|---|---|
| `FUN_00179314(table,a2,a3,a4)` | `FUN_004a5c44` | **Load**（写 `+0x00c`，脉冲 `0x101→0x001`） | — |
| `FUN_00179384(table,sel,fmt,ptr)` | `FUN_004a5e30` | ★ **Save**（写 `+0x010`，脉冲 `0x11→0x001`） | — |
| `FUN_001792c8()` | `FUN_004a5b6c` | 配置（不搬数据） | — |

★ 两处外围封装（`0x1793f4` / `0x1794a8`）分别用 `FUN_0017b570(7)` / `FUN_0017b570(8)` 做资源锁
⇒ **7 = Load 资源、8 = Save 资源**，与脉冲位 bit8/bit4 一一对应。

> ★★ **修正旧结论**：`P7_3DLUT_PATHS_2026-10-07.md` 把 `FUN_00179384` 描述为"load/save 封装"。
> 实测它是 **Save 路径**（mode=2）。View/Still/CS 三条线路用的都是 `FUN_00179314`（Load）。

## 3. ★ 五条应用线路

### 3.1 线路 A/B/C —— 图像流水线（C++ 虚方法，走 vtable）

BFS 从种子向上回溯，**「无上游」节点恰为 4 个，全部是 `CBackend_3dlut_*` 类的虚方法**——
这正是铁律 117 的情形：**虚函数没有直接 BL 调用者，字符串 xref 恒为空**。

| 线路 | 入口 | vtable 槽 | 消息 ID | 选表函数 | 汇入 |
|---|---|---|---|---|---|
| **A View** | `CBackend_3dlut_View::_load` = `FUN_0011e20c` | `0x58385c` | `0x10000002` | `FUN_0009a3e8`(静态4档) + `FUN_0009a408`(动态24档) | `FUN_00179314` |
| **B Still** | `CBackend_3dlut_Still::_load` = `FUN_0011e678` | `0x58390c` | `0x20000002` | **`FUN_0009a3c8`**（专用，无动态分支） | `FUN_00179314` |
| **C CS** | `CBackend_3dlut_CS` = `FUN_0011ebbc` | `0x5839ec` | 同上二选一 | `FUN_0009a3c8` | `FUN_00179314` |
| **D Base** | `CBackend_3dlut_Base` = `FUN_0011d14c` | — | `0x10000001` 错误路径 | — | `FUN_001792c8`（仅配置） |

- **消息 ID 分流**：`0x?0000002` 走"材质描述路径"（`FUN_00176884` + `thunk_FUN_003f2428`），**不灌 LUT**；
  否则才走选表 + `FUN_00179314`。
- **`FUN_0009a3e8` 实测返回值**（QEMU S6，参数 `(fmt, cbcr)`）：

| fmt | cbcr | 返回表地址 | 档位 |
|---|---|---|---|
| 0 | 0 | `0x81115200` | 肤色 |
| 1 | 0 | `0x81106B00` | 电影 |
| 0 | 1 | `0x81101E00` | 黑白 |
| 1 | 1 | `0x810FD100` | 标准 |

（与伪代码逐条一致，纯查表无转换——**这条线路完全可离线预测**。）

### 3.2 线路 E —— MCB 生产域（★ 本次新发现）

一段**打包好的完整应用序列**，位于 `0x3f2xxx / 0x3fbxxx` 区：

```
FUN_003f27ec  (0x3f27ec)  ← 调用者 0x175f94 / 0x176328 / 0x220590（应用层）
  └ FUN_003f222c (0x3f222c)
      └ FUN_003f3488 (0x3f3488)   ★ 3DLUT 应用打包
          ├ FUN_003fb1d4          MCB 准备（cmd 3）
          ├ FUN_003f2c60(r1=?, r2=idx)   ★★ 跳转表选表 → 装载
          │    └ 0x3fb4ac（参数胶水）
          │        └ FUN_003fb3b8(addr, sel, fmt)
          │            └ FUN_004a5c44 → FUN_004a5e30 → 寄存器
          ├ FUN_003fb368 → FUN_004a5b6c → FUN_004a5ff0   配置路径（不搬数据）
          ├ FUN_003fb51c → FUN_003f3fa4 族              MCB 寄存器读
          ├ FUN_003fb334                                MCB 系列操作
          └ FUN_003f56dc                                日志/事件
```

**跳转表 @ `0x3f2c70`（4 项，倒序）与对应的表地址**（QEMU 实测逐条命中）：

| idx (r2) | 跳转目标 | 字面量 | **表地址** |
|---|---|---|---|
| 1 | `0x3f2cc4` | `0x3f2cf4` | **`0x813D8800`** |
| 2 | `0x3f2cb0` | `0x3f2cf0` | **`0x813DD500`** |
| 3 | `0x3f2c9c` | `0x3f2cec` | **`0x813E2200`** |
| 4 | `0x3f2c80` | `0x3f2ce4` | **`0x813E6F00`** |
| 其他 | `0x3f2cd8` | `0x817D6AE4`（BSS 指针槽） | 运行时值 |

⇒ ★★ **这些地址在 BSS 区（> 镜像 0xC40000），是运行时缓冲**，
　且**四个地址两两相距 `0x4D00`** —— 与 View 档位池**完全相同的槽位粒度**，但**是另一组缓冲**。

> ⇒ **结论：3D LUT 至少有两套等距（0x4D00）表缓冲池**：
> 静态档位池（`0x810Fxxxx–0x8115xxxx`，给 View/Still/CS 用）
> 与 MCB 池（`0x813D8800–0x813E6F00`，给生产域用）。**此前只知前者。**

## 4. QEMU/Unicorn 复现（30 场景全部跑通）

**原理**：`p7_full.bin` 是 ARM 用户态 flat image，VA = 文件偏移 + `0x80000000`。
3D LUT 线路尾段是纯用户态代码（无 SVC / 无 MMU 依赖），
故可在 Unicorn 里直接执行，并在 MMIO 窗口挂写钩子，拿到**真实寄存器写序**。

### 4.1 `FUN_004a5c44(table, sel=0, fmt=0, 0)` —— Load 完整写序（实测）

```
[0x2082b000] <- 0x00000001    OnOff = 1
[0x2082b008] <- 0x00000000    Pulse bit0 = 0
[0x2082b008] <- 0x00000001    Pulse bit0 = 1        ← Acc 使能
[0x2082b00c] <- 0x94000000    ★ Load 目标地址 = table
[0x2082b004] <- 0x00000000    SelCbCr = 0
[0x2082b004] <- 0x00000000    SelLUT  = sel
[0x2082b008] <- 0x00000101    ★ Pulse: bit8 置位    ← DMA 启动
[0x2082b008] <- 0x00000001    ★ Pulse: bit8 清除    ← 脉冲结束
```

### 4.2 关键场景汇总

| 场景 | 输入 | 结果（实测） |
|---|---|---|
| `FUN_004cf484(1)` | — | `+0x008`: `0x100` → `0x00`（**Load 脉冲**） |
| `FUN_004cf484(2)` | — | `+0x008`: `0x10` → `0x00`（**Save 脉冲**） |
| `FUN_004cf4b4(a,b,1)` | — | `+0x00c` ← **a** |
| `FUN_004cf4b4(a,b,2)` | — | `+0x010` ← **b**（第 2 参，非第 1 参） |
| `FUN_004a5c44(t,sel,fmt,0)` | sel 0/1/2 × fmt 0/1 | 8–10 条写；`+0x00c`=t；`+0x004` 见 §4.3 |
| `FUN_004a5c44(t,3,·,·)` | sel=3 | `rc=-1`，**0 次寄存器写**（校验前置） |
| `FUN_00179384(t,0,0,0)` | — | ★ 写 `+0x010` + 脉冲 `0x11` ⇒ **Save 路径** |
| `FUN_00179384(t,3,·,·)` / `(t,0,2,·)` | 越界 | `rc=0xFFFFFFFF`，0 次写 |
| `FUN_00179384(t,2,·,·)` | sel=2 | 读未映射（**该 API 不支持 sel=2**，只构造 1 个描述符） |
| `FUN_0009a3e8(fmt,cbcr)` | 4 组 | 返回 4 档地址（见 §3.1 表）**逐条与伪代码一致** |
| `FUN_004a5b6c(&desc)` | ch=3 | `rc=-1`，0 次写 |
| `FUN_003f2c60(·,·,idx)` | idx 1..4 | ★ 写 `+0x00c` = **0x813D8800 / 0x813DD500 / 0x813E2200 / 0x813E6F00** |

**传参证据链（S8 实测，来自函数入口钩子）**：
```
FUN_003f2c60 → 0x3fb4ac(r0=0x94000000, r1=0x813d8800)
             → FUN_003fb3b8(0x813d8800, 0, 0)
             → FUN_004a5c44(0x813d8800, 0, 0, 0)     ★ 表地址确认为 0x813d8800
             → FUN_004a5e30(&desc@0x7f7fffc8)
             → FUN_004cf4b4(0x813d8800, 0x81792ab8, 1) → +0x00c
```

### 4.3 `fmt` 的实测语义（不是"采样格式"）

| sel | fmt=0 | fmt=1 |
|---|---|---|
| 0 | `+0x004` = `0x00000000` | `+0x004` = `0x00000100`（bit8 = ch0 使能） |
| 1 | `+0x004` = `0x00000010` | `+0x004` = `0x00001010`（bit12 = ch1 使能） |
| 2 | `+0x004` = `0x00000020` | `+0x004` = `0x00001120` |

⇒ `fmt` 被写进描述符 `+8` 字节，最终由 `FUN_004cf42c/444` 落到 **Cfg 的 ch0/ch1 使能位**。
　（旧文档称 `fmt` 为 "420/422 采样格式"——**实测是"通道使能"语义**。）

## 5. 对既有文档的修正清单

| 位置 | 旧表述 | 本次结论 |

| `P7_3DLUT_PATHS` §4.1 | `+0x00c`/`+0x010` = LUT0/LUT1 地址 | ★ **Load 目标地址 / Save 目标地址**（由 mode 选择，非双通道） |
