# 「画面向导 → 自定义1」在 p7 侧的触发链（能不能让 filmlab 直接触发）

> 问题（10-10 夜）：**能否让 filmlab 直接触发"画面向导 → 自定义1"，从而拿到全 7 维（含 R/G/B/HUE）？**
> 结论：**目前不能——但"不能"的边界第一次被压到一条具名消息上**：`class = 0x0107000E`。
> 全程离线（`p7_full.bin` 静态逆向 + capstone 反汇编），**未新增上机动作**。

---

## 0. 一句话

**"画面向导自定义1"在 p7 侧不是一条外部可见命令，而是一次"类别消息 + 槽变更通知"的内部动作。**
本次把这条链完整打通：

```
[外部?]  AP/app 发「类别消息」
   └─ FUN_00053330(selector)  ← 槽变更通知器（531 路跳表）
        └─ selector ∈ 0xda..0xe2  ⇒  0x545b8
             └─ FUN_00051ab8  ★ 档位应用：一次发全 8 个内部 id
                 0x10e, 0x130, 0x131, 0x132, 0x133, 0x10f, 0x110, 0x111
                 （值取自 p7 参数槽 218–226 = 0xda..0xe2）
   └─ FUN_0004c924(class=0x0107000E, ptr, len)  ← 类别应用 API
        └─ 0x4c9f4 thunk → b 0xd26b8（PW 应用例程）
             └─ 0x56c40（按当前风格查 profile 表）→ 0x65d6c → 0x6f2fc（写槽 0xda..0xe2）
```

★ 两条关键结论：
1. **R/G/B/HUE 的"进 ISP"动作发生在一个数据无参的函数里**（`FUN_00051ab8` 只读槽，不收外部值）——
   所以"推值"这条路永远够不到它们，**必须先让槽变**。
2. **让槽变的唯一外部语义 = 类别消息 `0x0107000E`**；它与 filmlab 现在用的"变量写"是**两套完全不同的编码与通路**。

## 1. 核心证据（地址全部为 `p7_full.bin` 文件偏移；VA = off + 0x80000000）

### 1.1 档位应用本体

| 项 | 值 |
|---|---|
| 函数 | `FUN_00051ab8` @ `0x51ab8`（640 B，Ghidra 因跳表数据误判为"bad instruction"）|
| 行为 | 连发 8 个**内部** id：`0x10e`(PWCOLOR) `0x130`/`0x131`/`0x132`(R/G/B) `0x133`(HUE) `0x10f`(SAT) `0x110`(SHARP) `0x111`(CON) |
| 取值 | `FUN_00063eb4(0xda..0xe2)` —— p7 **参数槽 218–226** |
| 编码 | 0x130–0x132（COLOR）：`((v*0xff/200)<<16) \| 0xff`；0x133/0x10f/0x110/0x111（SCALAR）：LUT @ `0x8056d628+0x220`（+0x220 → `0x56d848`）|
| 唯一调用点 | **`0x545b8`**（BL，全镜像仅此一处）|

### 1.2 触发者之一：槽变更通知器 `FUN_00053330(selector)`

```
0x53330  push {r4,lr}
0x5333c  mov  r4, r0                  ; r4 = selector
0x53348  bl   FUN_00063eb4            ; 读参数槽 selector
0x5334c  sub  r3, r4, #7
0x53350  movw r2, #0x212              ; 531
0x53360  ldrls pc, [pc, r3, lsl #2]   ; ★ 531 路跳表 @ 0x53368
0x53364  b    0x53bf4                 ; 默认（405 项落这里）
```

★ **解表结果（决定性）**：

| selector | 目标 | 含义 |
|---|---|---|
| `0xd8` (216) | `0x545ac` | 相邻分支 |
| **`0xda`..`0xe2` (218–226)** | **`0x545b8`** | ★ **全 7 维档位应用** |

⇒ **"某个 PW 参数槽被写"这个事件本身就会触发全 8 项下发**——这就是"7 维总是一起变"的原因。

跳表统计：531 项 / 83 个唯一目标；`0x53bf4`（默认，空槽）×405、`0x53d48`×34、**`0x545b8`×9**。

**它的调用者**：
* `0x4cd84` —— 小包装 `0x4cd74(selector)`：`if (r0 < 0) 记日志 else FUN_00053330(selector)`；
  `0x4cd74` 唯一调用者 = `0xe4850`（一组"参数块访问器"之一：`ldrsh r0,[r3]` → 尾调用），属 `0xe47c0` 访问器族（**间接/表注册**）。
* `0x56550`–`0x566c0` 约 100 个 thunk：`movw r0,#<槽号>; bl FUN_00053330; b 0x56548`（槽号 0xfe/0x105/0x106/0x115…）。

### 1.3 触发者之二：类别应用 API `FUN_0004c924(class, ptr, len)`

```
0x4c924  push {r3,r4,r5,lr}
0x4c928  mov  r5, r1
0x4c92c  mov  r1, r2
0x4c930  mov  r4, r0
0x4c934  bl   FUN_0004b9f4     ; ★ 类别白名单校验（class ∈ 0x102xxxx..0x10Cxxxx 一族）
0x4c938  cmp  r0, #0 / popne   ; 非 0 ⇒ 直接返回
0x4c948  add  r3, r4, #0xFEF8FFFF   ; r3 = class − 0x01070001
0x4c94c  cmp  r3, #0xd
0x4c950  ldrls pc, [pc, r3, lsl #2] ; 跳表 @ 0x4c958（14 项）
```

★ **解表结果**：

| k | class | thunk | → 目标 |
|---|---|---|---|
| 0 | `0x1070001` | `0x4ca04` | （三连调用 → `0xd4fdc`）|
| 1 | `0x1070002` | `0x4ca20` | `0xd2364` |
| 2 | `0x1070003` | `0x4c9b8` | `0xd25b4` |
| 3 | `0x1070004` | `0x4c998` | `0xd25bc` |
| 4/8/9/11 | — | `0x4c994`/`0x4c990` | 空/错误返回 |
| 5 | `0x1070006` | `0x4c9a8` | `0xd24e4` |
| 6 | `0x1070007` | `0x4c9b8`… | — |
| 7 | `0x1070008` | `0x4c9c8` | `0xd2754` |
| 10 | `0x107000B` | `0x4c9d8` | `0xd0370` |
| 12 | `0x107000D` | `0x4c9e4` | `0xd5180` |
| **13** | **`0x107000E`** | **`0x4c9f4`** | ★ **`0xd26b8` = PW 全 7 维档位应用** |

⇒ **`class = 0x0107000E` 就是「画面向导 → 自定义1」在 p7 侧的真身。**

### 1.4 PW 应用例程 `0xd26b8` 内部（为什么它是"真应用"）

```
0xd26b8  push {r4,lr}; r4 = r0
0xd26cc  bl 0x4e2c4c
0xd26d0  bl 0x56c40      ; ★ 按当前风格 profile 装载
0xd26d4  bl 0x51904
0xd26d8  bl 0x56898
0xd26dc  bl 0x51a9c
0xd2720  bl 0xd1fd4 / 0x4e30d8 / 0x9cf10 ...
0x56c40:  bl FUN_0004173c（取风格号，>7 则用 4）
          ldr r4, [lit + r0*4 + 0x53c]     ; 查内置 profile 表
          0x56d00 → bl FUN_00065d6c
0x65d6c → bl FUN_0006f2fc @0x6f2fc
0x6f2fc:  FUN_00064f0c(0xd5,0) / (0xd9,..) / (0xda,..) / (0xdc..0xe2,..)   ; ★ 写参数槽
```

⇒ **写槽（0x6f2fc）→ 槽变更事件 → 通知器 `FUN_00053330(0xda..0xe2)` → `0x51ab8` → 全 8 项下发 ISP**。
这条闭环把 §1.2 与 §1.1 接上了，也解释了"为何 `setusr` 只换风格名、搬不动 7 维参数"。

### 1.5 外部构造点（穷举）

全镜像中构造 `0x107000E` 的**只有一处**：`0x8df18`（在 `0x8ded8` 例程内，紧接 `0x1070001` 之后连发）。
其余 `0x107xxxx` 构造点共 19 处（`0x5b620`、`0x5b660`、`0x5bc54`、`0x5bc7c`、`0x5c608`、`0x5c63c`、`0xafcc0`、`0xbce1c`、`0xd26e4`、`0xe1d9c–0xe1de4`(循环展开 6..0) 等）。

这些"类别设置处理器"（`0x5b614` / `0x5b638` / `0x5bc1c` / `0xafc98` / `0x8ded8`）**全部没有直接调用者** ⇒ 它们是**函数指针表注册**的回调（与 `MCB_COMMAND_ENUM_TABLE` §5 的 `arp*NtfyFnc` 派发分组一致）。
`0x4ca40` = `FUN_0004c924(class, &v, 4)` 薄包装（唯一调用者 `0x8dfb8`）。

### 1.6 对照：filmlab 现在走的门

```
FUN_0004ccf4(ext_id, ptr, sz)      ; @0x4ccf4 = pwsend.arm 的落点
  └─ FUN_00051090 归一化（域 0x100–0x12e，47 项）
       └─ FUN_000d6b20(id, ptr, sz)   ; 变量发送器
```

* 这条门**只认"变量 id"**（域 `0x100–0x12e`），**不认"类别"**（编码是 `cat<<16|sub`，如 `0x0107000E`）；
* 且归一化器域外一律 `0xff` 拒收（`PW_ID_MAP_FULL` §6）⇒ `0x130–0x133` 也在界外。
⇒ **两条路互不相通**，这是"filmlab 够不到全 7 维"的结构性原因。

## 5. 本次新增的判据 / 铁律

| # | 内容 |
|---|---|
| 一 | **`0x51ab8` 是"值无参"的**——它只读 p7 参数槽 218–226。⇒ 任何"把值推给 ISP 以图改变 R/G/B/HUE"的尝试在结构上不可能成功（这解释了 10-10 probe3 的负结论根因）|
| 二 | **p7 有两个编号空间**：*变量 id*（外部门，0x100–0x12e）与*类别 class*（`cat<<16\|sub`，如 `0x0107000E`）。**判"外部能否驱动某功能"必须先问它属于哪个空间。** |
| 三 | **写参数槽 = 隐式触发应用**（selector 0xda–0xe2 → 0x51ab8）。⇒ "改某个槽"与"应用一次"在 p7 内是同一个动作，不要再去外部找"apply 命令"。 |
| 四 | Ghidra 在 `0x53374`–`0x56330`、`0x4c998` 一带因**内联跳表数据**整体误判（`bad instruction data`）⇒ **该区一律用 capstone 重扫 + 手工解跳表**，不要信伪代码。 |

## 7. 路 A 实测结论（10-10 夜 · 全离线）—— ⛔ 证伪

> 任务：复刻 `di-camera-app` 发送侧，取"类别消息"的 MCB CID + 报文，给 `pwsend` 加一条发送。
> 结论：**不存在可复刻的"类别消息"** —— class id 是 **p7 内部常量**，AP↔p7 之间没有它的字节级实体。

### 7.1 两扇门 = 全部（稳健证据：直接立即数扫描）

对整个 `libcapture-fw-prod.so`（734600 B）扫"构造 MCB 子命令"的立即数，`|0x1100` 与 `|0x1300` **各只有 1 处**：

| 位置 | 指令 | 所属函数 |
|---|---|---|
| `0x49eb8` | `orr r3, r3, #0x1100` | `SetUserDataMCB` @`0x49adc` |
| `0x49fbc` | `orr r3, r3, #0x1300` | `SetVariableDataMCB` @`0x49f84` |

⇒ **AP 侧任何"参数推送"都必经这两条函数中的一条**（或它们的便利封装）。

### 7.2 两扇门的完整字节级规格

```
SetUserDataMCB(uint16 id, uint32 value):
    ad = CMCBAdapter::getInstance()
    cmd = (uint16)(id | 0x1100)          ★ 0x49eb8
    return ad->SetParam(cmd, len = 4, &value)     ← 固定 4 字节

SetVariableDataMCB(uint16 id, ptr, uint16 len):
    ad = ...
    cmd = (uint16)((id - 0xff) | 0x1300)  ★ 0x49fbc
    return ad->SetParam(cmd, len, ptr)

CMCBAdapter::SetParam(u16 cmd, u16 len, u8* data):        @0x83ea4
    return CMulticoreBridge::Send(CID = 0x81, cmd, len, data)   ← 唯一出口
```
★ 与既有结论一致（`ATTR_BUS_MCB` §「cmd=(id-0xff)|0x1300 / CID 0x81」），本次补上**姊妹门 0x1100**。

**用户态便利层**（都在 capfw 内，app 直接导入）：
| API | 地址/尺寸 | 备注 |
|---|---|---|
| `mm_camera_set_usr_attributes` | `0x2a574` / 636 B | = usr 门（0x11xx）|
| `mm_camera_set_var_attributes` | `0x2a7f0` / 764 B | = var 门（0x13xx）|
| `mm_camera_set_notification_callback/id` | `0x29afc` / `0x29d04` | 回调与 notify id |

★ **`mm_camera_set_var_attributes` 内含类别重映射**（`0x2aa00-0x2aa74`）：当 `id == 0x10b` 时把值 `0x010b0001/0002/0000` **改写为** `0x010c0001/0002/0`
⇒ **反证 `cat<<16|sub` 的类别编码确实是这条路的载荷**（与 p7 侧 `0x0107xxxx` 同构）。

### 7.3 p7 侧：class 0x0107000E 没有任何静态引用（5 路取证全 0 命中）

对 `p7_full.bin` 穷举下列五种引用方式，目标 = `FUN_0008de6c`（含 class 0x107000E 的例程）与其调用者 `FUN_000121e4`：

| # | 取证方式 | 命中 |
|---|---|---|
| 1 | `BL / BLX / B` 直接分支（全镜像逐 4 字节） | **0** |
| 2 | 4 字节字面量指针（`0x8008de6c` / `0x800121e4` …） | **0** |
| 3 | 相对跳表（`p+v(+δ) == target`，δ ∈ {0,4,8,-8}） | **0** |
| 4 | PIC 取址 `add rX, pc, #imm` 解出目标 == 目标 | **0** |
| 5 | `movw/movt` 构造函数地址（**铁律 121** 的必查项） | **0** |

⇒ **结论**：`FUN_0008de6c`（PW 全维 apply 所在）+ `FUN_000121e4`（"模式/初始化批次"例程：`0x121e4 → 0x2ba20 → 0x8e9bc → 0x8de6c → 0x21f9ec`）
在**静态镜像里不可达**。二者属**运行时 RAM 派发表**（不可静态定位）或该构建的死代码。

★ 这与"只有人点一次向导才生效"完全自洽：**app 的动作不产生任何指向 class 0x107000E 的字节流**。

### 7.4 路 A 的三个副产品（都留档）

| # | 内容 |
|---|---|
| 1 | **usr 门（`cmd = id\|0x1100`）的完整规格** —— 目前 `pwsend.arm` 只覆盖 var 门，usr 门未覆盖（可加，但语义上等同于 `st cap capdtm setusr`，未见额外收益）|
| 2 | 工具：`raw8/repro/capfw/plt_calls.py`（自校验 PLT 映射 + 调用点反查，支持任意 ELF；**含成链过滤**）|
| 3 | ★ **踩坑**：`di-camera-app` 是 **ARM/Thumb 混合**，对它做"全 .text ARM 线性反汇编"会产出**错位命中**（实测把 `bl #0xb22b0` 误判为 `bl #0xab980`）⇒ **判该 app 的调用点必须按段判 ARM/Thumb**，否则结论无效 |

### 7.5 改判：真正的杠杆与建议

| 路 | 结论 |
|---|---|
| **A 复刻消息** | ⛔ **死路**（本次证伪）。连带：**"外部可驱动全 7 维"在静态分析下无任何入口** |
| B 键注入 | ⛔ 已实测不生效 |
