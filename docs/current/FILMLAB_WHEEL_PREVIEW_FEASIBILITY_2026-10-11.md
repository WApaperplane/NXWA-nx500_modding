# 「FilmLab 滚轮切换 + 实时预览」可行性（2026-10-11）

> 问题（木一）：**把 mod 功能迁移到固件之后，能不能实现 FilmLab 的按键/滚轮滚动切换 + 预览效果**
> —— 参考手机滤镜切换、以及相机自带的「图片向导 / 画面向导」？
>
> 结论前置：**你举的那个参照物，相机自己就是。** 相机原生「画面向导」本来就是"滚轮滚列表 + 实时预览"，
> 而它的「自定义 1/2/3」槽**内容由 mod 决定，且已实机验证"机身 UI 可见"**。
> ⇒ **这个体验今天就能有，零固件成本**；天花板不是"能不能"，而是**只有 3 个可见槽**。
> **把它"迁到固件"（改 p7）不会让它变得更可能** —— 那是层次错误。

## 3. ★ 三条可走的路（按推荐度）

### 路 1 —— 零固件：把「自定义 1/2/3」当滤镜轮（**今天就有**）
```
filmlab.sh preset <recipe> 9|10|11    → 写 prefman slot（+ save）
用户：机身「画面向导」→ 波轮滚到「自定义1/2/3」 → 实时预览 ✓
```
- **这是已有的、已验证的形态**（C2 ✅）。缺点：**只有 3 条**，且要进菜单。
- **判据**：`filmlab.sh check`（ISP 手上的 7 维 == 槽值）+ 机身 UI 可见 + 成片带效果

### 路 2 —— 零固件：借原生波轮「转一格换一条」（**需先做实验 E1**）
```
若 波轮转动 → 触发 EV_UP.sh / EV_DOWN.sh   （★ 上机实测）
则 把 filmlab.sh cycle 挂到 EV_UP/EV_DOWN
  → 转一格 = 换下一条配方 + popup_timeout 弹配方名（★ 相机原生 OSD，不是我们画的）
```
- **零固件、零自绘 UI**，最接近"手机滤镜轮"的**成本/收益比**。
- 风险：**内核先消费按键**是已确立的架构约束（长按/连击/组合键不可得）；波轮的**转动**是否也走钩子，属未测。

### 路 3 —— 零固件：把内置 9 档预置也换成配方（**需先做实验 E2**）
- **推论依据**：`PW_BASE = 0xa3ec` 的官方命名是 `APPPREF_EFFECT_STANDARD_R_COLOR`
  ⇒ **slot 0 就是「标准」**，即 9 个内置预置（标准/鲜明/肖像/风景/悠远/复古/清爽/宁静/古典）
  **在 prefman 里同样是按 `PW_BASE + slot*52` 寻址的**。
- **若**机身 UI 读的是 prefman 值（而不是编译期常量表），**则原生滚轮列表会从 3 条变 12 条**。
- 代价/风险：内置预置被改（**必须先备份 slot 0–8**）；「标准」被改坏会让相机默认观感异常（可 `reset` 回）。
- **明确标注**：★ 这是**推论，未验证**，别当结论用。

## 4. 「预览效果」的技术账（与"滚动"分开算）

| 项 | 现状 | 说明 |
|---|---|---|
| PW 三维直推（SAT/SHARP/CON） | ✅ 已实测 | 画面**秒级**变化 |
| 3D LUT 预览直灌 | ✅ 已通 | LUT1 + `lutsentinel` 守护；**单次切换延迟未测**（决定"够不够流畅"） |
| 全 7 维一键（外部） | 🔶 A1 待刷 | `probe3` 判据已写死 |
| 全 7 维（机身路径） | ✅ 已通 | 代价 = 在画面向导里选一次 |
| **成片带 LUT** | ❌ E4 负结论 | 定式 = 预览直灌 + 成片后处理 |
| 成片带 PW 7 维 | ✅ | 走的是相机自己的成像管线 |

★ **手机 vs 相机的物理差（别照搬预期）**：
手机 = 触摸滑动 + 多帧 GPU 合成 ⇒ 连续、无级；
相机 = **单核 CPU** + **离散波轮格** + **内核先消费按键**。
⇒ **"连续滑动"在 NX500 上做不出来**；现实上限是 **"逐格切换 + 秒级预览"**。
