## 1. 上机 runbook（灰度两步法）

### 刷写方式（与 U4/U5 同一条链）
```
1) 把待刷包【改名为 nx500.bin】放到 SD 卡根目录
2) 机身：MENU → Setting → Device Information → Firmware Update → Body Firmware Update
3) 等"完成"→ 自动重启
★ 刷机后 telnet 有 ~4 min Refused 窗口（Ping 通、21/23 拒）—— 别急判砖，等 5 min 重试
```

> ★ **10-14 损失面终审（刷前必读；详见 `CAMERA_ONLINE_PROBE_2026-10-13.md` 附 D）**：
> ① **`/opt/usr/nx-ks/`（p14）不在升级写入面**（`parttab` `opt-usr=image:none` + 十段映射全锁定）⇒ **无需防刷备份**；T2 投递物同理；

> SD 卡放好主包 3 件套 `info.tg`/`nx_cs.adj`/`install.sh`（素材在本地工作副本 `E:/NXWA/NX-WA-2.88.0-nxwa.1/`）

> ③ 刷后预期节奏：~4 min 内 telnet 恢复；**别急判砖**。

### Step 1 —— 路径绕行自检（零行为变化）
**目的**：验证 `0x11504` 所在的 254B 零区**在运行期不会被覆盖**。
该档位把 `0x510b0` 重定向到 `0x11504`，而 `0x11504` 只有一条 `b 0x80051394` —— 与原路径**逐位等价**（多绕一跳）。

| # | 动作 | 判据 |
|---|---|---|
| 1 | 刷 `step1` 包 | UI 接受 + 完成 + 自动重启；telnet 恢复（等 ~4 min） |
| 2 | 触发一次越界调用：`st cap capdtm setvar 0x12f <v> 4` | **必须仍被拒收**（rc≠0 / varlist 无变化）；相机不崩 |
| 3 | 常规工况覆盖：拍照 / 录像 / 待机唤醒 各若干次 | 无异常、无死机；`loadavg` 无飙升 |
| 4 | ★ 回读 0x11504 区（可选、只读）：`dd if=/dev/mmcblk0p7` 该偏移 24B | 若内容被改成垃圾 ⇒ **区域不安全，停止，改选址（候选 B/C）** |
| 5 | 稳定运行 ≥ 数小时 | 进 Step 2 |

> Step 1 的**唯一失败模式**是"零区被运行期覆盖" → p7 会立刻异常，**损失最小**。

## 2. 判定边界（知情风险）

| 现象 | 含义 | 处置 |
|---|---|---|
| Step1 后 `0x12f` 不再被拒收 | 重定向/中转编码有误 | 停止，回滚，复查 `asm_verify` |
| Step1 后相机异常/死机 | `0x11504` 零区被运行时占用 | 回滚；改用候选 B（`0x11010`）或 C（`0x57xxxx`） |
| Step2 R/G/B/HUE 写后 **`varlist` 有变化但画面无感** | 还有"渲染消费侧"条件（如 PWCOLOR 聚合项联动） | **另一层任务，不在本 patch 范围**（已知边界） |
| 刷入被 UI 判灰 | 版本未高于设备 | 确认 `/etc/version.info`；包内 version 已是 1.16 |

## 3. 回滚（三条路，任选）

1. **原地回滚（最省）**：本补丁只动 2 处，原字节已知（`b7 00 00 ea` + 24B 零）。重打一版即回原样。
2. **官方件回滚**：刷官方 `NX500_v1.12.bin`（改名 `nx500.bin`）—— **但会被 UI 反降级拦**（设备若显示 1.16）。
   ⇒ 实用做法：用 `slp_version_bump.py` 把官方件版本提到 1.17 再刷（内容仍是官方原样）。
3. **分区级参照**：`raw8/emmcbak/p7_orig.bin` / `p7.bin`（md5 均 `f19441df58f8c2b0116ce99773bd5143`）
   = p7 分区从未被触碰的原始态，可作比对基准。

> ★ 提醒：**boot0/boot1 绝不碰**。
