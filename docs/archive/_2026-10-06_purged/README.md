## ★ 被否证的三条核心结论

| 文档 | 曾断言 | 实际 |
|---|---|---|
| `LUT_FORMAT_FINAL_2026-10-06.md`<br>`LUT_FORMAT_V3_STATIC_ANALYSIS_2026-10-06.md` | 硬件表 = **19652** 字节 | ★★ **不成立**（等距数组法套错了对象） |
| 同上 / `IDENTITY_LUT_TEST_2026-10-06.md` | 硬件表 = **29478** 字节（17³×3×u16） | ★★ **不成立** |
| 全部"读回验证"类文档 | 读回数据与源表逐字节一致 ⇒ 已进硬件 | ★★ **作废：自证循环** |

### ★★ 自证循环是什么

```
我用 load_lut  把表写进 CMA 缓冲 A
再用 save_lut 从缓冲 A 读回
⇒ 读到的是我自己写进去的数据
⇒ 只证明 DMA 读写通路对称，完全不能证明硬件 SRAM 里的内容
```

实测证据：把**全新的清零缓冲**交给 `save_lut`，读回**全零**
（9 种 sel × cbcr × fmt 组合全试，均为 0）
⇒ `save_lut` 根本没有把硬件表写出来

## ★★ 仍然有效的部分

虽然结论失效，但以下内容**经实机验证依然成立**：

### 1. p7 侧静态分析（capstone 逐层验证过）
```
View::_load  @0x11e20c → @0x3837d0（7 条指令）→ 4 档静态表
Still::_load @0x11e678 → @0x382b30（三参数 + Picture Wizard）→ 24 档动态表
FUN_000f6474() = socket 收"数据口袋"（688 字节缓冲）
```

### 2. 硬件寄存器实测值
```
EP 3D LUT @ 0x2082b000 size 4096
出厂 LUT0 = 0x81115200（肤色档），LUT1 = 0
Cfg = 0x00000100（bit8=1）
```

### 3. 4 个静态档初值（p7 .data 常量）
```
0x3837f0 → 0x810fd100（标准）  0x3837f4 → 0x81101e00（黑白）
0x3837f8 → 0x81106b00（电影）  0x3837fc → 0x81115200（肤色）
```

### 4. CMA 硬事实
```
cma: reserved 288MiB @ 94000000 / 72MiB @ 8f800000
★ /dev/d5_sma 的 ioctl 只报告第一个区
★ 0x94000000 全占（ISP WDMA 工作区），写入会卡死整机
★ 0x8f800000 有约 4MB 连续空闲
```

### 5. p7 会抢回 `+0x00c`
20 次连续采样实测：半按快门对焦后，`LUT0` 从我的地址变回 `0x81115200`。

1. ★★ **`save_lut` 读不出硬件表** —— 别用它验证任何东西
