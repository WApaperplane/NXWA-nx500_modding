## 一、★★★ 头号结论：**p7 在官方固件内，有官方退路**

昨晚的核心悬案是「SLP 里的 `T-Kernel` 是不是 eMMC 的 p7」。**答案是：是。**

```
SLP[5]  offset=15680257  len=12075648  crc32=df679d3b
     ↓ 逐字节比对
p7.bin  (rtos/rom.bin)   len=12075648   ★★★ 完全一致
```

| 验证项 | 结果 |
|---|---|
| SLP[5] 镜像 vs 实机 p7 前 12075648 字节 | **逐字节完全相等** |
| SLP 镜像之后的 p7 尾部非零字节 | **0 个**（全是零填充）⇒ SLP 镜像是完整有效数据 |
| 与 22:00 抽的 `p7_full.bin` 比对 | md5 均 `bd44db7feb8dc2f5`，一致 |

⇒ **改坏 p7 后，把官方 `NX500_v1.12.bin` 放 SD 卡，走机身菜单
Settings → Device Information → Firmware Update 即可整机恢复。**

⇒ **昨晚那句「T-Kernel 2.01.03 是给 Cortex-A7 的 TRON 镜像」的推测是错的。**
它就是 **ISP 固件本体**（`0x4e0000ea` = 我们 p7 向量表的第一条指令，`0xea` 是 ARM 模式 `B` 的opcode）。
> ⚠️ **2026-10-06 修正**：此处原标注的"Cortex-M"**已作废**。`0xf96d0512` 不是 `sdiv`
> （ARM 模式 SDIV 应为 `0xF710_F001`），且向量表 8 项全是 **ARM 模式 B 指令**而非绝对地址
> ⇒ p7 是 **ARM 模式（A32）** 代码。详见 `P7_ISP_FIRMWARE_ANALYSIS_2026-10-05.md` 顶部修正块。

⇒ 恢复粒度是**整机级**：rootfs + rtos + 所有分区一起刷回官方状态。

## 二、SLP 容器格式（已完整解出）

### 2.1 文件头 `FwFileMeta`（64 字节）

| 偏移 | 大小 | 字段 | 实测值 |
|---|---|---|---|
| `0x00` | 4s | magic | `SLP\0` |
| `0x04` | 8s | version | `1.12` ★**刷写器比对的就是这个字符串** |
| `0x0C` | 16s | project | `NX500` |
| `0x1C` | 16s | version_date | `NX500GLU0APC1`（板号，机型匹配用） |
| `0x2C` | 1b | has_pcache | `10` ⇒ **V2 格式**（>1 时 10 个 image header 内嵌在文件头） |
| `0x2D` | 4I | pcache_offset + reserved | `0` |

struct 格式：`<4s8s16s16sbI15s>`（来自 ge0rg 源码，**已验证正确**）

### 2.2 Image header（24 字节 × 10）

struct 格式：`<IIII8s>` = `img_len / crc32 / img_offset / magic / extra`

★ **`crc32` 用的是 `CRC-32/JAMCRC`，不是 zlib 的 CRC-32。**
标准写法：`zlib.crc32(data) ^ 0xFFFFFFFF`。已在 **4 个分区上逐一验证 MATCH**。

### 2.3 布局自证

```
头部 = 64 (meta) + 10×24 (headers) = 304 字节
数据 = 10 个镜像紧密排列
304 + 352,121,131 = 352,121,435 = 文件大小  ✔ 完全吻合
```

## 四、★★★ 已实现并验证 SLP 重打包

ge0rg 的 `slp-firmware.py` **作者明说只能解析、不能重打包**。本项目补上了这一块。

### 4.1 安全设计

| # | 设计 | 理由 |
|---|---|---|
| 1 | **默认 dry-run**，不加 `--write` 只报告不落盘 | 防止误产出一个坏固件 |
| 2 | **只改指定分区**，其余 9 个字节级原样搬运 | 最小改动面 |
| 3 | **自动重算** `img_offset` 与 `crc32`（含后续全部分区） | 长度变化时不漏 |
| 4 | **crc32 固定 JAMCRC 变体**，与官方 4/4 验证一致 | 避免刷写器因校验失败拒绝 |
| 5 | **拒绝改变** `version` / `project` / `version_date` | 昨晚查明「版本检查是纯字符串比较」 |
| 6 | **`--verify-back` 回读校验** | 产物自己解析一遍，逐分区比对 |
| 7 | **自动裁剪**尾部零填充 | ★ 块设备备份是 30MB，SLP 镜像是 11.52MB，不裁会把后续分区全顶走 |
| 8 | 裁掉的尾部若**含非零数据则警告** | 可能是真实内容丢失 |
| 9 | `part0.magic` 强制 `0xffffffff` | 官方解析器的硬性前置检查 |

### 4.2 三层验证（全部通过）

**① 解析自测**：官方固件 10/10 分区 crc32 **全部 MATCH**

**② 空替换往返自测**（最强判据）：
```
用实机 p7 原样替换 SLP[5] → 重打包 → 与官方原文件逐字节比对
官方 md5 = df08b6f802d548ed03bb9e974c9a9bbd
产物 md5 = df08b6f802d548ed03bb9e974c9a9bbd
★★ 完全一致 ⇒ 重打包器【无损】
```
（证明我们的格式理解 100% 正确 —— 任何字段理解偏差都会导致 md5 不同）

**③ 真实改动演练**（改 p7 的 1 个 bit：`0x10`→`0x11` @ `0x200`）：
```
新 crc32[5] = 2c737ece  (原 df679d3b)
回读校验: meta 一致 / 分区5 内容==替换值 / 总体 PASS
第三方交叉验证（ge0rg 原版工具解析我们的产物）:
  分区5 crc = 2c737ece   ← 只有这一个变了
  其余 9 个 crc 全部与官方原文件一致   ← 证明零副作用
```

### 4.3 用法

```bash
# 只看分区表
python test_server/slp/slp_tool.py NX500_v1.12.bin

# 解包全部分区
python test_server/slp/slp_tool.py NX500_v1.12.bin -x /tmp/slp_parts

# 演练（dry-run，不落盘）
python test_server/slp/slp_tool.py NX500_v1.12.bin -r 5 -f my_p7.bin

# 真正生成
python test_server/slp/slp_tool.py NX500_v1.12.bin -r 5 -f my_p7.bin -O out.bin --write
```

## 五、★ 未验证事项（动手前必读）

| # | 未验证 | 风险 | 建议的验证方式 |
|---|---|---|---|
| 1 | **官方刷写流程是否接受非等长镜像** | 中 | 先做等长替换（本工具默认裁到原长） |
| 2 | **刷写器是否校验分区 crc32** | 中 | 若校验，JAMCRC 已算好；不校验则更安全 |
| 3 | **刷写器是否还有 SLP 之外的完整性校验**（如整体签名/hash） | ★ 高 | 只能实测：先刷一个「内容等价」的镜像，看相机是否接受 |
| 4 | **刷写过程中断电的后果** | ★ 高 | 官方流程应该有断点保护，未查证 |
| 5 | 刷写后 p7 实际生效（bootloader 是否真的从 p7 加载） | ★ 高 | 刷一个可观测的改动（如在字符串里插标记）验证 |

### ⚠️ 最安全的下一步

**不直接改 ISP 固件。先做「等价替换验证刷写链路」：**

1. 用工具重打包一个**内容与官方完全一致**的 `.bin`（就是我们的 `roundtrip.bin`，
   md5 与官方相同）
2. 放 SD 卡走官方流程刷
3. ★ **如果相机接受并正常工作 ⇒ 刷写链路验证完毕，我们对 SLP 的理解得到实机确认**
4. 如果相机拒绝 ⇒ 拒绝信息本身就是最有价值的数据（说明有我们没发现的校验）

**这一步零风险**（内容与官方字节相同，刷坏了也是刷回官方状态），
却能把最大的未知变成已知。**比直接改 p7 理性得多。**

## 六、这条路与「改固件」的取舍

| 维度 | 改 p7 固件（重打包刷回） | 改 rootfs / 用正规通道 |
|---|---|---|
| 上限 | ★★★★★ 任意改 ISP 逻辑 | ★★★ 7 维参数 / 3×3 矩阵 / gamma 曲线 |
| 社区先例 | ❌ **132 issues 零命中，无人做过** | ✅ FilmLab 已在跑 |
| 失败恢复 | ★ **官方 .bin 整机恢复**（本轮新证） | ✅ 单分区回滚（已验证过） |
| 是否需解 SLP | ✅ 已解完并双向验证 | ❌ 不需要 |
| 风险 | ★★★★ 未知校验项 | ★★ 低 |

⇒ **两条路现在都可行了**。但建议顺序：
1. 先做上面的「等价替换」刷写链路验证（零风险）
2. 优先走**正规通道**（gamma 曲线 / 3×3 矩阵）—— 语义清晰、可回滚、无需刷机
3. 只有当正规通道表达不了创意时，才动固件
